# 影像检索基线与升级方案

当前特征为 `histogram-rgb8-v1`，RGB 8×8×8 颜色直方图、512 维、L2 归一化，使用余弦相似度。数据库记录特征版本和生成时间；上传和补算会写入版本，查询排除未知及不同版本的向量。

三张现有影像已完成同版本重算，公开状态保持一张公开、两张草稿。当前没有经独立标注的临床相似/不相似配对，不能报告临床 Precision、Recall 或诊断准确率。

已完成的工程基线：同一纯色图缩放相似度为 1，不同纯色为 0；将双色图像旋转、改变颜色空间位置，相似度仍接近 1。三张实存影像缩放后的相似度约为 1、0.99984、0.99939。结果表明特征能稳定表达颜色分布，也直接证明它不能识别空间解剖结构。公开影像查询会排除自身，因此唯一公开图没有其他公开候选属于正常空结果。

复现命令（`backend` 目录）：

```powershell
python -m scripts.eval_image_baseline
python -m scripts.backfill_image_features          # 预览缺失或版本过期项
python -m scripts.backfill_image_features --apply  # 显式重算，发布状态不变
```

明细位于 `data/eval/image_baseline_20261104.json`。这份结果是工程检验，没有医学语义标签。

建议下一步先收集有来源与许可的多样影像，覆盖不同术式、解剖部位和成像设备；由两位熟悉领域的标注者分别定义“相似”维度，再复核分歧。按患者或原文来源划分开发和留出集，避免同一病例图片同时出现在两组。样本数量需按候选规模和误差区间确定，不以三张图作模型选择。

随后在同一固定留出集比较当前基线、通用视觉编码器和候选医学编码器，记录 Recall@K、人工相关性、查询延迟及资源消耗。只有出现可重复收益后再切换：新增独立特征列与索引、记录编码器标识/权重摘要/预处理/维度、全量计算、核验覆盖率、灰度切换并保留旧索引用于回退。即使维度相同，也不得混合不同编码器的特征。
