# 模块拆解与技术流转（工程视角）

> 课题：基于术中影像与 RAG 的结直肠手术围术期多模态知识库智能问答系统
> 定位：本科毕业设计，**医学教学辅助**，不可用于临床诊断。
> 本文只讲工程实现：代码在哪、处理逻辑怎么走、输入输出是什么。

## 0. 技术栈口径说明（先看这一节，避免答辩说错）

任务书列的技术栈是「Python、LangChain、pgvector、Neo4j、RRF、交叉编码器重排、GLM」。
以实际代码为准；2026-11-08 已将主问答流程迁移到 LangChain LCEL：

| 任务书 | 实际实现 | 说明 |
|--------|----------|------|
| LangChain | **已引入：langchain-core 1.7.6 / LCEL** | `rag_chain.py` 使用 RunnableSequence、RunnableBranch、RunnableGenerator 和 ChatPromptTemplate 编排检索、证据门控、提示词、生成及校验；`rag_service.py` 的同步和流式入口实际调用该链，多轮问答复用。底层检索算法和 HTTP 模型适配继续复用。 |
| GLM | **视觉侧用的是 GLM**：`glm-4v-flash`（智谱）；**文本侧默认 `deepseek-flash`** | 二者都是 OpenAI 兼容协议，`llm_client` 只换了 `base_url` 与 `model`，改 `.env` 即可切到 `glm-4-flash`，代码零改动。答辩应按实际配置说明文本模型与视觉模型，不应把协议兼容说成已采用或已验证 GLM 文本生成。 |

其余技术栈与任务书一致：Python 3.12、FastAPI、pgvector 0.8.7、Neo4j 5.26、RRF、bge-reranker-v2-m3、BGE-M3。

## 1. 七个工程模块

### ① 多模态知识采集预处理模块（文献文本 + 术中影像）

**工程实现内容**

| 步骤 | 代码位置 | 处理逻辑 |
|------|----------|----------|
| 文本解析 | `app/etl/manual_import.py::parse_markdown` | 解析人工录入的结构化 Markdown：首部键值对抽元数据（标题/作者/期刊/年份/证据等级/分期/语种），正文按 `##` 切章节，谱表题注单独归入 `abstract_sections` |
| 控制字符清洗 | `manual_import.py::_sanitize_control_chars` | 正则剔除 `[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]`。**这是踩过坑的**：某个英文 PDF 的公式字形带 NUL，直接导致 PostgreSQL 报 `cannot contain NUL (0x00) bytes` 整批入库失败 |
| 语种判定 | `manual_import.py::detect_language` | 三级判定：元数据显式 `语种` → 标题汉字数（≥4 判中文）或标题拉丁字母数（≥15 且汉字<2 判英文）→ 正文汉字占比 ≥0.15 兜底 |
| 去重 | `app/etl/ingest.py::_find_existing` | 三级命中：PMID → DOI → 标题归一化。中文指南通常无 PMID/DOI，必须有标题这一路，否则每次重复导入都新建记录 |
| 切块 | `app/etl/chunker.py::build_chunks` | 按章节边界切，超长再按句子切；滑动窗口留 **64 token 重叠**；每块记录 `section / page_start / page_end / char_start / char_end`，页码与字符偏移是后续"引用定位到原文"的前提 |
| 关键词生成 | `ingest.py` 调 `tokenize_for_search` | 中文按 **2-gram** 切分（pg_trgm 对非 ASCII 无效，中文必须自己切），结果存 `text[]` 列供 GIN 索引 |
| 影像入库 | `app/api/v1/images.py::upload_image`、`app/repositories/image_repo.py::create` | 校验格式（JPG/PNG/WebP/BMP）与大小（≤8MB）→ 算 SHA256 去重 → 落本地文件系统 → 记录宽高/格式/大小/术式/部位/分期/来源 |

**使用技术**：Python、pymupdf（PDF 取文本与字号定位标题）、正则、BGE-M3 分词侧 bigram、PostgreSQL `text[]` + GIN。

**输入**
- 中文指南/共识与中文期刊论文：PDF → Markdown，或直接人工录入 Markdown
- 英文文献：**全文 PDF**（不用 PubMed 题录——题录只有摘要，撑不起全文引用）
- 术中影像：谱片文件 + 表单元数据（标题、术式、解剖部位、围术期分期、来源、是否公开）

**输出**
- `ParsedArticle`（标题、作者、期刊、年份、DOI、证据等级、分期、语种、章节文本）
- `TextChunk` 列表（正文、块序号、章节、页码、字符偏移、bigram、token 数）
- 影像记录（存储路径、SHA256、宽高、元数据）

> 边界：影像**只做元数据标注与谱文检索**，不做病灶分割、不做影像分类识别。影像识别（分割/检测模型）列为后续拓展。

### ② 知识库存储模块（PostgreSQL + pgvector、Neo4j、影像表）

**工程实现内容**

| 存储 | 表/结构 | 关键设计 |
|------|---------|----------|
| 文献主表 | `kb_document` | 标题、作者、期刊、年份、DOI、PMID、`evidence_level`、`phase`、`language`、`doc_type`、`is_active`（下架用软删除，保住历史引用链） |
| 文本块表 | `kb_chunk` | `content`、`embedding vector(1024)`、`bigrams text[]`、`section`、`page_start/page_end`、`char_start/char_end`、`chunk_index` |
| 向量索引 | `ivfflat/hnsw` on `embedding` | HNSW，余弦距离；1024 维对应 BGE-M3 |
| 关键词索引 | `GIN(bigrams)` | 支持 `bigrams && ARRAY[...]` 求交集 |
| 影像表 | `kb_image` | 存储键、SHA256（唯一）、宽高、`vlm_analysis`（客观描述缓存）、`vlm_interpretation`（**综合解读快照 JSONB**，切页/刷新后可直接渲染）、术式/部位/分期/来源 |
| 谱谱 | Neo4j `:Entity` + 10 类关系 | 单标签 + `type` 属性（不用多标签，实体类型由 LLM 抽取，标签随类型增长会失控）；关系如 `TREATS / PREVENTS / CAUSES_COMPLICATION / HAS_RISK_FACTOR / LOCATED_AT / USES_DRUG …`；对 `name` 建唯一约束 |

**使用技术**：PostgreSQL 16 + pgvector 0.8.7、SQLAlchemy 2.0、Alembic 式手写 `ALTER TABLE`（本项目未用完整迁移框架）、Neo4j 5.26 + 官方 Python Driver。

**输入**：解析后的文献与文本块、向量、bigram；谱谱抽取出的实体关系三元组。

**输出**：可按向量/关键词/谱谱三种方式查询的存储层；对上层暴露 `search_repo`、`image_repo`、`graph_client`。

> 现状（2026-10 实测）：上架文献 **109 篇**（中文 75：指南/共识 30 + 中文论文 45；英文全文 34），文本块 **3,772**，谱谱 **1,423 实体 / 1,380 关系 / 10 类关系**。

### ③ Embedding 与多路召回模块

**工程实现内容**

**向量化**
- `app/services/model_registry.py`：懒加载 + 单例。BGE-M3 放 GPU，`use_fp16 = (device=="cuda")`，batch 32。
- `app/services/search_service.py::embed_texts`：统一出口，带 **NaN 自愈**——检测到非有限值就 `reload_embedder(force_fp32=True)` 后重试一次，仍异常抛 `EmbeddingInvalidError` 由接口层转 HTTP 503。
  （起因：长驻进程 fp16 溢出导致查询向量全 NaN，PostgreSQL 直接报 `NaN not allowed in vector`。）

**三路召回**（`app/services/hybrid_search.py`）

| 路径 | 实现 | 参数 |
|------|------|------|
| 向量召回 | `embedding <=> 查询向量` 余弦近邻 | `retrieve_top_k_vector=50` |
| 关键词召回 | `bigrams && ARRAY[查询bigram]`，再算**覆盖率**过滤（交集/查询 bigram 数 ≥ `min_keyword_overlap=0.3`） | `retrieve_top_k_keyword=50` |
| 谱谱召回 | 从问题抽实体 → Neo4j 查邻居关系 → 回映射到引用这些实体的文本块 | `retrieve_top_k_graph=20` |

**融合**：RRF（Reciprocal Rank Fusion）
- 公式 `score(d) = Σ w_i / (k + rank_i(d))`，`k=60`
- 权重 `vector=1.0 / keyword=0.3 / graph=0.6`（谱谱权重居中：有增益但精度低于向量，不能让噪声盖过主路）
- 融合后截断 `rrf_limit=80` 作为重排候选池
- 每篇文献最多保留 `max_chunks_per_document=3` 块，防单篇刷屏
- **只用名次不用分数**：三路分数量纲不同（余弦相似度 / 覆盖率 / 谱距离），直接加权不可比

**使用技术**：BGE-M3（1024 维）、PyTorch + CUDA、pgvector HNSW、PostgreSQL GIN、RRF。

**输入**：自然语言查询（可选分期过滤、`top_k`、`recall_mode` 用于消融）。

**输出**：融合排序后的候选块列表（含 `rrf_score`、各路名次与权重、耗时明细）。

### ④ 重排 + 三道校验防线模块（幻觉抑制）

**工程实现内容**

**重排**（`hybrid_search.py::rerank`）
- 交叉编码器 `bge-reranker-v2-m3`，输入 `(查询, 块正文)` 逐对打分，取 `top_n = top_k * 2`
- 双塔向量召回是"粗筛"，交叉编码器是"精排"：把 query 和 doc 拼在一起过模型，能捕捉否定、限定词、数值条件这类细粒度差异

**三道防线**

| 防线 | 代码 | 逻辑 | 触发后的行为 |
|------|------|------|--------------|
| ① 检索校验 | `rag_service.answer` / `answer_stream` | 检索结果为空 → 直接返回；最高分 < `min_evidence_score=0.05` → 拒绝作答，**不调用 LLM** | 返回"证据不足"提示 + 建议（换术语/放宽分期/确认覆盖范围） |
| ② 引用溯源 | `app/services/citation.py::extract_citation_indices` / `build_citations` | 从答案正文正则抽 `[n]` → 与送进 prompt 的证据编号比对 → **剔除越界/编造的编号**并记入 `invalid_citations` | 答案保留文字、删掉无效标记；前端可展示"无效引用数" |
| ③ 数值核验 | `citation.py::extract_numeric_claims` / `verify_numeric_claims` | 正则抽百分比、比值、样本量、年份区间等数值主张 → 回查证据文本是否出现该数值（含单位/范围容差） | 无据数值记入 `unsupported_numbers`，生成 `numeric_warning`，但不篡改答案（宁可告警不擅改医学表述） |

> 关键设计：**证据不足时不调用大模型**。这是从源头杜绝"无据生成"的第一道闸，比事后校验更彻底——模型没机会编。

**使用技术**：bge-reranker-v2-m3、正则与归一化比对、FastAPI 异常映射（`EmbeddingInvalidError → 503`）。

**输入**：RRF 融合后的候选池 + 原始查询。

**输出**：`top_k` 条精排证据（含 `rerank_score`）、`invalid_citations`、`unsupported_numbers`、`numeric_warning`。

### ⑤ 大模型答案生成模块

**工程实现内容**

- `app/services/llm_client.py`：OpenAI 兼容 Chat Completions 封装。统一处理超时、重试、`reasoning_content`（推理模型的思考过程）、usage 统计；密钥缺失时给明确报错而不是 500。
- `app/services/prompts.py`：系统提示词固化四条硬约束
  1. 只能使用给定证据作答，不得引入外部知识
  2. 每个结论句后必须标 `[n]`，编号对应给定证据
  3. 证据不足以回答时必须明确说"资料不足"，并说明缺什么
  4. 不给出个体化诊疗建议，输出附合规声明
- 生成模式三种：
  - 非流式 `/api/qa`
  - **流式 SSE `/api/qa/stream`**（前端实际使用，逐 delta 推送）
  - 多轮 `/api/chat/stream`：先查询改写（指代消解）→ 意谱/分期识别 → 检索 → 生成，`meta` 事件先于检索返回，前端可立即展示"系统如何理解问题"
- 意谱识别用 `response_format={"type":"json_object"}` 强制 JSON，解析失败降级为 `(general, knowledge, 0.0)` 不中断主流程。
- 指令类问题（"你是谁""你能做什么"）由 `app/services/meta_intent.py` 正则识别，**短路不检索**，直接返回自我介绍并说明能力边界。

**使用技术**：OpenAI 兼容协议、httpx、SSE、JSON mode、流式增量解析。

**输入**：问题（+ 多轮时的会话历史）、`top_k` 条证据、分期/意谱约束。

**输出**：答案 Markdown（含 `[n]` 标记）、引用列表、校验结果、分段耗时（检索/重排/生成）、`disclaimer`。

### ⑥ 前后端交互接口模块

**工程实现内容**

- 后端：FastAPI，**共 70 个接口**（`app/api/v1/` 下 9 个路由文件）。
  - 问答：`POST /api/qa`、`POST /api/qa/stream`
  - 多轮：`POST /api/chat/stream`、`GET /api/chat/{sid}`（会话历史，含引用明细）、`DELETE /api/chat/{sid}`
  - 检索与统计：`POST /api/search`、`GET /api/stats`、`GET /api/chunks/{id}`（引用"展开原文"取全文）
  - 影像：上传/列表/详情/原谱/解读/删除
  - 知识库维护：文档列表、详情、上下架、删除、重建索引
  - 认证与管理：登录、当前用户、改密、用户管理、系统配置
- 流式协议：SSE，事件类型 `meta / retrieval / delta / done / error`，按 `\n\n` 分帧；`ssePost()` 前端统一解析，问答页与会诊页共用。
- 认证：JWT（HS256），bcrypt 口令（**强制 72 字节截断**，否则新版 bcrypt 直接报错）；权限中间件「默认拒绝 + 公开白名单」（`/api/qa`、`/api/search`、`/api/chat`、`/api/images`、`/api/chunks` 等）。
- 前端：Vue 3 + TypeScript + Vite + Element Plus + Pinia，6 个功能页（问答/会诊/影像/知识库/系统状态/系统管理）+ 404。
  - 引用面板抽成共享组件 `CitationPanel.vue`，两页复用（曾因各写一份导致"会诊页不能展开原文"）。

**使用技术**：FastAPI、Pydantic v2、python-jose、passlib+bcrypt、SSE、Vue 3、Pinia、Axios。

**输入**：HTTP/SSE 请求（JSON 或 multipart）、JWT。

**输出**：JSON 响应 / SSE 事件流 / 谱片二进制流。

### ⑦ 评测与消融实验模块

**工程实现内容**

- 评测集：`data/eval/` 下中英文双集（`qa_dataset_v2_zh` / `_en`），人工构造问题 + 标准答案要点。
- 检索指标：`backend/scripts/eval_retrieval.py`，计算 **Recall@5**、MRR，逐题记录命中情况。
- 生成指标：`generation_quality.json` 记录忠实度（答案要点是否都能在证据中找到）、引用准确率（`[n]` 指向的文献是否真的支持该句）。
- 消融：`recall_mode` 支持 `vector / keyword / graph / hybrid` 四档，同一评测集逐档跑，产出对比表；另有"证据加权开关""重排开关"等维度。
- 校核脚本：`audit_pdf_dirs.py`（PDF 目录与库内记录对账）、`restore_corpus.py`（快照回滚）。

**使用技术**：Python 脚本 + 直接调用服务层、JSON 结果落盘、指标聚合。

**输入**：评测集问题、当前语料、检索参数组合。

**输出**：指标 JSON + 对比表（用作论文第 5 章实验数据）。

> 现状：英文 Recall@5 0.632、中文 0.449、忠实度 0.766、引用准确率 0.807、无效引用率 0.000。中文指标偏低，主要原因是中文指南多为长句叙述、按章节切块后单块语义跨度大，属已知问题。

## 2. 完整技术路线数据流

### 2.1 离线入库流程

```
① 素材准备
   ├─ 中文指南/共识、中文期刊论文  → PDF 取文本（pymupdf）→ 结构化 Markdown
   ├─ 英文文献                    → 全文 PDF → 结构化 Markdown
   └─ 术中影像                    → 谱片文件（JPEG/PNG/WebP/BMP）
        │
        ▼
② 解析（parse_markdown）
   ├─ 首部键值对 → 元数据（标题/作者/期刊/年份/证据等级/分期/语种）
   ├─ 正文按 ## 切章节；谱表题注归入 abstract_sections
   └─ 清洗控制字符（NUL 等）
        │
        ▼
③ 语种判定（detect_language）
   元数据显式 → 标题汉字/拉丁字母数 → 正文汉字占比 ≥0.15 兜底
        │
        ▼
④ 去重（_find_existing）
   ├─ 命中 PMID  ─┐
   ├─ 命中 DOI   ─┼→ 视为已存在 → 更新：删旧块 → 重建块（幂等）
   └─ 标题归一化 ─┘
   └─ 全部未命中 → 新建文档记录
        │
        ▼
⑤ 切块（build_chunks）
   按章节 → 超长按句子切 → 64 token 重叠
   每块记录 section / page_start / page_end / char_start / char_end
        │
        ├──────────────────────────────┐
        ▼                              ▼
⑥ 向量化（BGE-M3, 1024 维, batch 32）   ⑦ 关键词（中文 bigram → text[]）
   └─ 检测到 NaN → 重载 fp32 重试一次
        │                              │
        └──────────────┬───────────────┘
                       ▼
⑧ 写入 PostgreSQL（kb_document / kb_chunk）
   ├─ embedding 建 HNSW 索引
   └─ bigrams 建 GIN 索引
                       │
                       ▼
⑨ 谱谱构建（另起一条支路）
   LLM 从文本块抽实体与关系（结果带缓存，避免重复花钱）
   → 归一化去重 → 写入 Neo4j（:Entity 单标签 + type 属性，10 类关系，name 唯一约束）
                       │
                       ▼
⑩ 影像入库（与文本并行）
   格式/大小校验 → SHA256 去重（命中则复用旧记录）→ 落盘
   → 写 kb_image（标题/术式/部位/分期/来源/是否公开）
   → 用户点「辅助解读」时：GLM-4V 生成客观描述 → 缓存 vlm_analysis
        │
        ▼
⑪ 入库校验
   统计文献数/块数/向量覆盖/AI 失败块数；与源目录对账（audit_pdf_dirs）
```

**分支要点**

| 分支 | 条件 | 行为 |
|------|------|------|
| 无可用摘要 | `skip_no_abstract` 且 `is_usable=False` | 跳过该文献，计入 `documents_skipped` |
| 去重命中 | PMID/DOI/标题任一命中 | 更新而非新建，先删旧块再重建，保证幂等 |
| 向量异常 | 检测到 NaN/Inf | 重载 embedder 为 fp32 重试一次，仍失败则该批报错并跳过 |
| 影像重复 | SHA256 已存在 | 直接复用旧记录，不重复占盘 |

### 2.2 在线问答流程

```
用户提问
   │
   ▼
① 入口分流（多轮页额外做）
   ├─ 指令类问题（"你是谁"/"你能做什么"/"怎么用"）→ meta_intent 命中
   │     → 直接返回自我介绍（不检索、不调 LLM）→ 结束
   └─ 普通问题 → 继续
   │
   ▼
② 查询改写（仅多轮，且已有历史）
   结合历史把"它的发生率是多少"还原为完整问题
   → 产出 rewritten_query，并标记 rewritten=True
   │
   ▼
③ 意谱与分期识别（LLM, JSON mode）
   产出 phase（preop/intraop/postop/general）+ intent + confidence
   → 解析失败降级为 (general, knowledge, 0.0)，不中断
   │
   ▼
④ 多路召回（三路并行）
   ├─ 向量：embedding <=> query_vector      top 50
   ├─ 关键词：bigrams && 查询bigram，覆盖率≥0.3   top 50
   └─ 谱谱：抽实体 → 查邻居 → 映射回文本块       top 20
   │
   ▼
⑤ RRF 融合
   score = Σ w_i/(60 + rank_i)，w = 1.0 / 0.3 / 0.6
   → 截断 80 条 → 每篇文献最多留 3 块
   │
   ▼
⑥ 交叉编码器重排（bge-reranker-v2-m3）
   逐对打分 → 取 top_n = top_k × 2
   │
   ▼
⑦ 【分支判断】证据是否充足
   │
   ├─ 检索结果为空  或  最高分 < min_evidence_score(0.05)
   │     └─→ 拒绝生成
   │           返回「知识库未检索到相关证据，无法给出有依据的回答」
   │           + 建议（换术语/放宽分期/确认覆盖范围）
   │           ✗ 不调用大模型 —— 这是防幻觉的第一道闸
   │
   └─ 证据充足 → 继续
   │
   ▼
⑧ 组装 Prompt 并生成（流式）
   系统提示：只用给定证据 / 每句标 [n] / 不足则明说 / 不给诊疗建议
   → SSE 逐 delta 推送（前端逐字渲染）
   │
   ▼
⑨ 引用溯源校验
   抽答案中的 [n] → 与证据编号比对
   ├─ 编号越界或未提供 → 记入 invalid_citations → 从正文剔除该标记
   └─ 合法 → 绑定文献（标题/期刊/年份/页码/章节/原文片段）→ 右侧引用面板
   │
   ▼
⑩ 数值主张核验
   抽百分比/比值/样本量 → 回查证据文本
   ├─ 找到依据 → 通过
   └─ 找不到   → 记入 unsupported_numbers + 生成 numeric_warning（不擅改答案）
   │
   ▼
⑪ 组装响应
   answer + citations + invalid_citations + unsupported_numbers +
   numeric_warning + 分段耗时 + disclaimer
   （多轮场景同时落一条 ConversationTurn：问题/答案/改写/分期/意谱/引用明细）
   │
   ▼
⑫ 前端渲染
   正文（[n] 可点击 → 定位右侧卡片）｜右侧引用面板（可展开取全文）｜耗时与校验提示
```

**在线分支汇总**

| 分支 | 条件 | 行为 |
|------|------|------|
| 指令类问题 | 正则命中身份/能力/用法 | 不检索，直接答复 |
| 无证据 | 检索为空 | 拒绝生成，返回建议 |
| 证据偏弱 | 最高分 < 0.05 | 同上，拒绝生成（**关键：不调 LLM**） |
| 引用无效 | `[n]` 超出证据范围 | 剔除标记 + 计数上报 |
| 数值无据 | 数值在证据中找不到 | 告警但不改答案 |
| 向量异常 | 查询向量 NaN | 重载 fp32 重试；仍失败 → HTTP 503 并提示稍后重试 |
| 会话过期 | 前端持有的 session_id 后端已淘汰 | 返回 404，前端清本地记录，提示重新提问 |

### 2.3 影像辅助解读（在线，独立分支）

```
上传影像（手填术式 / 部位 / 分期 / 来源）→ 落盘 + SHA256 去重
   │
   ▼
【分支】是否已有 vlm_analysis 缓存
   ├─ 有 → 复用客观描述（不再花云端调用）
   └─ 无 → GLM-4V-Flash 生成客观描述 → 写入 vlm_analysis
   │
   ▼
由描述构造检索查询（描述文本本身作为 query）
   │
   ▼
走 2.2 的 ④~⑥（多路召回 → RRF → 重排）
   │
   ▼
【分支】证据是否充足
   ├─ 不足 → 只给客观描述 + 明确「文献证据不足，无法给出辅助解读」
   └─ 充足 → 结合证据生成辅助解读（结论须标出处）
   │
   ▼
写入 vlm_interpretation（JSONB 快照）→ 再次打开直接渲染，不必重跑
   │
   ▼
输出：客观描述 + 检索查询 + 辅助解读 + 引用 + 合规声明
```

> 边界：视觉模型**只描述所见，不下诊断**；结论性表述必须由文献证据支撑。
> 不做病灶分割、不做影像分类识别——这两项列为后续拓展。

## 3. 三句话记住整条链路

1. **离线**：PDF/Markdown → 解析清洗 → 三级去重 → 按章节切块（留页码偏移）→ BGE-M3 向量 + 中文 bigram → PostgreSQL；另抽实体关系进 Neo4j；影像只存元数据与描述。
2. **在线**：改写 → 意谱分期 → 三路召回（向量/关键词/谱谱）→ RRF 融合 → 交叉编码器重排 → **证据够不够？不够就拒答、不调模型** → 够则生成 → 引用校验 + 数值核验 → 带引用返回。
3. **防幻觉**：证据门槛挡在生成之前，引用校验与数值核验兜在生成之后，三道防线各管一段。
