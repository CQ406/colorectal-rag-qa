# 模块功能说明书

> 本文按**功能**描述系统每个模块：做什么、怎么用、输入输出是什么、有哪些限制。
> 与 `模块详解.md` 的区别：那一份讲「怎么实现的、为什么这样设计」，这一份讲「能干什么、怎么操作」。
>
> 数据基准：109 篇文献 / 3,772 个文本块（中文 75、英文 34）。

---

## 模块地图

```
用户功能（7 个页面）
├── 智能问答        单轮提问 → 带引用的答案
├── 多轮会诊        连续追问，自动还原指代
├── 影像解读        上传术中影像 → 有文献依据的辅助解读
├── 典型病例        草稿维护 / 管理员发布 / 文本相似匹配
├── 知识库          语料概览 / 文献管理 / 更新知识库 / 更新历史
├── 系统状态        依赖健康度、模型状态、语料统计
└── 系统管理        用户、问答日志、反馈、审计、参数配置

支撑服务（后台）
├── 认证与权限      JWT 登录、角色权限、账号管理
├── 检索服务        多路召回 + 融合 + 重排
├── 问答服务        证据组装、生成、引用校验、数值核验
├── 模型管理        检索模型的加载/卸载/自检
└── 健康检查        存活与就绪探针

离线流程
├── 文献采集与入库  PubMed 采集、中文指南录入、切分、向量化
└── 评测            评测集生成、检索指标、生成质量
```

# 第一部分　用户功能模块

## 1. 智能问答

**定位**：一次提问得到一个答案，每处结论可点开看出处。这是系统的主界面。

### 功能点

| 功能 | 说明 |
|------|------|
| 自然语言提问 | 直接输入临床问题，支持中文口语化表达（如「吻合口漏怎么防」） |
| 围术期分期筛选 | 可选 术前/术中/术后/通用，缩小检索范围 |
| 流式回答 | 答案逐字输出，先看到首句再等完整答案 |
| 引用标注 | 答案中每处结论带 `[n]` 编号，可点击 |
| 引用详情面板 | 点编号展开：文献题名、期刊、年份、证据等级、原文片段 |
| 证据不足提示 | 检索不到足够证据时，**不调用大模型**，直接提示「证据不足」 |
| 数值核验提示 | 答案中找不到出处的数值会被标出 |
| 耗时与用量 | 显示检索耗时、生成耗时、token 用量 |

### 使用路径

```
打开「智能问答」→ 输入问题 → 点发送
  → 选择围术期分期（可选）
  → 流式显示答案
  → 点击答案中的 [1] → 右侧展开引用详情
  → 如需追溯原文，看引用片段中的章节名
```

### 输入 / 输出

| | 内容 |
|---|---|
| 输入 | `question`（必填）、`phase`（可选）、`top_k`（可选，默认 5） |
| 输出 | `answer`（含 `[n]` 标记）、`citations[]`（每条含 doc_id、title、section、score、evidence_level）、`timings`、`usage`、`insufficient`（布尔） |

### 对应接口

| 接口 | 用途 |
|------|------|
| `POST /api/qa` | 非流式，一次返回完整答案 |
| `POST /api/qa/stream` | 流式（SSE），逐字返回 |

### 关键限制

- **答案只依据检索到的证据**。证据相关性低于阈值时返回「证据不足」，不会用模型的内部知识作答。
- 中文提问检索英文文献时依靠向量跨语言匹配，精度低于中文对中文。

## 2. 多轮会诊

**定位**：围绕同一病例连续追问，系统自动把「它」「这个」还原成完整问题。

### 功能点

| 功能 | 说明 |
|------|------|
| 多轮上下文 | 同一会话内保留最近 10 轮对话 |
| 查询改写 | 追问自动补全为独立可检索的查询 |
| 意图识别 | 判定问题类型：概念定义 / 诊断评估 / 处理治疗 / 证据预后 / 比较选择 |
| 分期识别 | 自动判断问题属于术前、术中还是术后 |
| 会话管理 | 新建、查看历史、清除会话 |
| 会话统计 | 活跃会话数、总消息数 |

### 使用路径

```
打开「多轮会诊」→ 新建会话
  → 问「直肠癌吻合口漏的危险因素有哪些」
  → 追问「它的发生率是多少？」  ← 系统自动补全为「直肠癌吻合口漏的发生率」
  → 继续追问「那怎么预防」
  → 左侧可切换历史会话
```

### 输入 / 输出

| | 内容 |
|---|---|
| 输入 | `session_id`（首次可空）、`message`、`phase`（可选） |
| 输出 | 同智能问答，另加 `rewritten_query`（改写后的查询）、`intent`、`detected_phase` |

### 对应接口

| 接口 | 用途 |
|------|------|
| `POST /api/chat` | 多轮问答 |
| `GET /api/chat/stats` | 会话统计 |
| `GET /api/chat/{session_id}` | 读取会话历史 |
| `DELETE /api/chat/{session_id}` | 清除会话 |

### 关键限制

- 会话存在**内存**中（最多 200 个，LRU 淘汰），**后端重启后会话丢失**。
- 追问含指代词或过短时才触发改写，已完整的提问不会被改写。

## 3. 影像解读

**定位**：上传术中影像，得到客观描述 + 有文献依据的辅助解读。

### 功能点

| 功能 | 说明 |
|------|------|
| 影像上传 | 支持 PNG/JPEG 等常见格式，记录标题、部位、术式、备注 |
| 影像列表 | 缩略图浏览、按部位/术式筛选 |
| 草稿工作区 | 有维护权限的医师和管理员可浏览及编辑草稿；管理员审核发布或取消公开 |
| 草稿原图 | 通过携带 Bearer 令牌的请求获取预览，访客无法访问 |
| 分页浏览 | 每页 24 张，按分期或关键词筛选时回到第一页 |
| 原图查看 | 点击查看原图 |
| 元数据编辑 | 修改标题、部位、备注 |
| 影像删除 | 从知识库移除 |
| 库统计 | 影像总数、总大小、按部位分布 |
| **辅助解读** | 三阶段：① 多模态模型客观描述 → ② 由描述构造检索 → ③ 结合文献证据给解读 |
| **相似影像检索** | 上传时生成 512 维 RGB 颜色直方图，按 pgvector 余弦相似度检索公开样例；相似度仅表达颜色分布相似，不代表诊断置信度 |
| **相关病例推荐** | 用影像描述检索已发布病例，推荐诊断、术式和相似度 |
| 解读缓存 | 同一影像重复解读直接返回缓存，避免重复调用 |

### 使用路径

```
打开「影像解读」→ 上传影像
  → 选择影像 → 点「辅助解读」
  → 第一阶段：显示模型对影像的客观描述
  → 第二阶段：显示检索到的文献证据
  → 第三阶段：显示综合解读（每处结论带引用）
```

### 输入 / 输出

| | 内容 |
|---|---|
| 上传 | 文件 + `title`、`site`（部位）、`procedure`（术式）、`note` |
| 解读 | `image_id`；输出 `description`（客观描述）、`evidence[]`、`interpretation`（带引用的解读）、`disclaimer` |

### 对应接口

| 接口 | 用途 |
|------|------|
| `POST /api/images` | 上传 |
| `GET /api/images` | 列表 |
| `GET /api/images/stats` | 统计 |
| `GET /api/images/manage` | 维护人员草稿与已发布影像列表 |
| `GET /api/images/manage/stats` | 维护人员全部影像统计 |
| `GET /api/images/manage/{id}` | 维护人员影像详情（包括草稿） |
| `GET /api/images/manage/{id}/raw` | 受保护原图（含草稿，禁止缓存） |
| `GET /api/images/{id}` | 详情 |
| `GET /api/images/{id}/raw` | 原图 |
| `PATCH /api/images/{id}` | 改元数据 |
| `DELETE /api/images/{id}` | 删除 |
| `POST /api/images/analyze` | 辅助解读 |
| `POST /api/images/similar` | 影像特征相似检索（可传入库影像 ID 或 base64） |

## 4. 典型病例

**定位**：维护公开脱敏的结直肠手术病例，支持文本相似匹配并与影像解读联动。

| 功能 | 接口 | 说明 |
|------|------|------|
| 列表与筛选 | `GET /api/cases` | 按关键词、分期和术式筛选，仅返回已发布病例 |
| 详情 | `GET /api/cases/{id}` | 展示病史、检查、诊断、术式、手术记录和预后 |
| 相似病例 | `POST /api/cases/search` | pgvector 语义向量检索；未生成向量时降级文本匹配，病例库为空时无结果 |
| 新增/编辑 | `POST/PATCH /api/cases` | 医师可建草稿；管理员审核后发布 |
| 删除 | `DELETE /api/cases/{id}` | 管理员操作并记录审计日志 |

病例仅限公开或脱敏资料。发布权限属于管理员；上传前须确认影像来源与病例材料均可公开使用。

### 关键限制

- **定位为辅助解读，不是诊断**。模型只做客观描述，结论性表述必须由文献佐证，输出固定带合规声明。
- 首次解读需冷启动模型，约 **113 秒**；热态 + 缓存约 **14 秒**。
- 影像文件存本地磁盘，不入向量库（以元数据与描述参与检索）。

## 5. 知识库

**定位**：查看语料构成、审核文献、触发更新。这是管理员维护语料的入口。

### 4.1 语料概览

| 功能 | 说明 |
|------|------|
| 规模统计 | 文献数、文本块数、已向量化数 |
| 语种构成 | 中文 / 英文 篇数（按实际文字自动判定） |
| 证据等级分布 | 指南 / 系统评价 / RCT / 队列 / 综述 / 其他 |
| 分期覆盖 | 术前 / 术中 / 术后 / 通用 |
| 审核进度 | 已审核 / 待审核 比例 |
| 质量报告 | 六维评估 + 自动生成的维护建议 + 异常清单（缺摘要、缺标识符、未向量化） |

### 4.2 文献管理

| 功能 | 说明 |
|------|------|
| 文献列表 | 分页浏览，显示题名、分期、证据等级、语种、块数、状态 |
| 八维筛选 | 标题/作者/期刊/DOI/PMID 关键词、分期、证据等级、语种、审核状态、上架状态、起始年份 |
| 单篇审核 | 通过 / 驳回（驳回自动下架） |
| 批量审核 | 勾选多篇一次性通过或驳回 |
| 上架 / 下架 | 控制文献是否进入检索池（下架可恢复） |
| 彻底删除 | 从库中物理删除（含文本块），需二次确认 |
| 文献详情 | 查看摘要、元数据、分块情况、审核信息 |
| 语种标记 | 中文显示绿色标签，英文显示灰色标签 |

### 4.3 更新知识库

| 功能 | 说明 |
|------|------|
| 增量采集 | 选模式（按主题 / 按分期 / 补充），后台从 PubMed 采集新文献 |
| 重新向量化 | 对未向量化或需重建的文本块重新生成向量 |
| 任务进度 | 实时显示当前步骤、已处理数量、耗时 |
| 后台执行 | 提交后立即返回任务号，前端轮询进度，不阻塞页面 |

### 4.4 更新历史

| 功能 | 说明 |
|------|------|
| 批次列表 | 每次更新一个批次，记录检索式、参数、新增/更新数、耗时、操作人 |
| 批次详情 | 该批次涉及的具体文献 |

### 对应接口

| 接口 | 用途 |
|------|------|
| `GET /api/admin/kb/documents` | 列表（含筛选与分页） |
| `GET /api/admin/kb/documents/{id}` | 详情 |
| `PUT /api/admin/kb/documents/{id}/review` | 单篇审核 |
| `POST /api/admin/kb/documents/batch-review` | 批量审核 |
| `PUT /api/admin/kb/documents/{id}/active` | 上架/下架 |
| `DELETE /api/admin/kb/documents/{id}` | 彻底删除 |
| `GET /api/admin/kb/quality` | 质量报告 |
| `POST /api/admin/kb/collect` | 触发采集 |
| `POST /api/admin/kb/search` | 触发检索式试跑 |
| `POST /api/admin/kb/vectorize` | 触发向量化 |
| `GET /api/admin/kb/tasks` `/tasks/{id}` | 任务列表与进度 |
| `GET /api/admin/kb/batches` `/batches/{id}` | 批次历史 |

### 关键限制

- 写操作（审核、上下架、删除、采集、向量化）**仅管理员可用**；医师只能查看。
- 「下架」是主操作（可恢复、历史引用仍有效），「彻底删除」藏在详情对话框内并需二次确认。
- 重复导入同一文献不会产生重复记录，按题名归一化后**更新**原记录。

## 5. 系统状态

**定位**：一眼看出系统是否健康、模型是否就绪、语料是否在检索池内。

### 功能点

| 功能 | 说明 |
|------|------|
| 依赖健康度 | PostgreSQL / Neo4j / Redis / 存储 各自的连通状态与延迟 |
| 模型状态 | BGE-M3 与重排模型是否已加载、显存占用 |
| 语料统计 | 上架文献数、可检索文本块数、已向量化数 |
| 检索自检 | 输入一段文本，返回其向量维度与前若干维数值，用于确认向量化正常 |
| 服务信息 | 版本、启动时间、API 前缀 |

### 对应接口

| 接口 | 用途 |
|------|------|
| `GET /api/health` | 含全部依赖的健康检查 |
| `GET /api/health/live` | 存活探针（仅进程） |
| `GET /api/health/ready` | 就绪探针（依赖可用） |
| `GET /api/stats` | 上架语料统计 |
| `GET /api/stats/library` | 全库统计（含已下架，供核对入库进度） |
| `GET /api/models/status` | 模型加载状态 |
| `POST /api/models/load` | 预加载检索模型 |
| `POST /api/models/unload` | 卸载模型释放显存 |
| `POST /api/models/embed` | 向量化自检 |

### 关键限制

- **模型惰性加载**：首次提问需等约 60 秒（含模型加载）。演示前建议先调 `POST /api/models/load` 预热。

## 6. 系统管理

| 功能 | 说明 |

### 6.4 参数配置

| 功能 | 说明 |

| 批量修改 | 一次提交多项 |

| 接口 | 用途 |
|------|------|

| `GET /api/auth/me` | 当前用户 |

| `GET /api/users` `/users/stats` `/users/{id}` | 用户查询 |

| `POST /api/admin/audit/purge` | 清理日志 |
| `GET/PUT /api/admin/config` | 配置 |
| `PUT /api/admin/config/batch` | 批量配置 |
| `POST /api/admin/config/reset` | 恢复默认 |
| `GET /api/admin/overview` | 管理总览 |

### 关键限制

- 角色是**固定两种**（管理员 21 项权限、医师 9 项），不支持自由组合权限位。
- 医师**不能**审核、上架、删除文献，也不能管理用户——这些直接影响全系统答题依据，属发布决策。

# 第二部分　支撑服务

## 7. 认证与权限

**功能**：判断「你是谁」与「你能做什么」。

| 能力 | 说明 |
|------|------|
| 口令哈希 | bcrypt，按 72 字节截断（bcrypt 5.0 超长会抛错） |
| 令牌签发 | JWT HS256，8 小时有效 |
| 令牌校验 | 每次请求校验签名与用户当前状态 |
| 默认拒绝 | 未在公开白名单中的路径一律要求登录 |
| 公开路径 | 登录、健康检查、文档等 |
| 审计写入 | 登录成功/失败、权限拒绝都记审计 |

## 8. 检索服务

**功能**：把用户问题变成一组带分数的证据片段。

| 能力 | 说明 |
|------|------|
| 向量召回 | BGE-M3 编码问题 → HNSW 近似最近邻 |
| 关键词召回 | 中文 bigram + GIN 倒排；带最小重叠比例过滤 |
| 图谱召回 | 实体识别 → Neo4j 关系扩展 → 回溯来源文本块 |
| 融合 | RRF 按名次加权合并（向量 1.0 / 关键词 0.3 / 图谱 0.6） |
| 重排 | 交叉编码器逐对精排，取前 N |
| 证据等级加权 | 按指南 > 系统评价 > RCT 调整分值 |
| 分期过滤 | 只召回指定分期的文本块 |
| 统计 | 上架/全库文本块数、分期与证据分布 |

## 9. 问答服务

**功能**：从证据到带引用的答案。

| 能力 | 说明 |
|------|------|
| 证据门槛 | 最高分低于阈值 → 不调模型，返回证据不足 |
| 提示词组装 | 系统角色 + 回答要求 + 证据片段（编号）+ 问题 |
| 生成 | DeepSeek 接口，支持流式 |
| 引用解析 | 把 `[n]` 映射到具体证据，剔除不存在的编号 |
| 引用校验 | 记录无效引用数（幻觉信号） |
| 数值核验 | 抽取答案中的数值，逐个在证据中查找，标记无据数值 |
| 日志 | 写入问答日志（问题、引用数、耗时、信号） |

## 10. 模型管理

**功能**：控制本地检索模型的加载与卸载。

| 能力 | 说明 |
|------|------|
| 惰性加载 | 首次使用时加载，避免启动占用显存 |
| 手动预加载 | `POST /models/load`，演示前预热 |
| 手动卸载 | `POST /models/unload`，释放显存 |
| 状态查询 | 是否加载、模型路径、设备 |
| 向量自检 | 输入文本返回向量维度与前几维，确认编码正常 |

## 11. 健康检查

**功能**：给部署环境做存活与就绪判断。

| 接口 | 检查内容 | 用途 |
|------|---------|------|
| `/health/live` | 进程是否活着 | 容器存活探针 |
| `/health/ready` | 依赖是否可用 | 容器就绪探针 |
| `/health` | 全部依赖 + 延迟 | 人工排查 |

# 第三部分　离线流程

## 12. 文献采集与入库

**功能**：把外部文献变成可检索的文本块。

### 12.1 两条入库通道

| 通道 | 来源 | 说明 |
|------|------|------|
| **中文指南录入** | 用户提供的 PDF / Markdown | 解析 → 清洗 → 章节切分 → 标注 → 入库。当前 75 篇 |
| **PubMed 采集** | PubMed E-utilities | 检索式 → 采集题录与摘要 → 去重 → 分类 → 入库。按需由管理员触发 |

### 12.2 处理链

```
采集/录入
  → 去重（题名归一化）
  → 语种判定（标题优先）
  → 分期与证据等级标注（分类器 + 人工声明可覆盖）
  → 切分（标题块 / 章节块 / 整段块）
  → 生成向量（BGE-M3）与 bigram 词元
  → 写入 PostgreSQL
  → 抽取实体关系 → 写入 Neo4j
```

### 12.3 命令行入口

```bash
python -m app.etl.cli manual --dry-run    # 预览
python -m app.etl.cli manual              # 导入
python -m app.etl.cli collect --mode ...  # PubMed 采集
python -m app.etl.cli vectorize           # 补向量化
```

### 12.4 录入文件格式

```markdown
# 指南标题

**作者**：编写组
**期刊**：中华胃肠外科杂志
**年份**：2025
**证据等级**：guideline
**分期**：general
**语种**：zh          ← 可选，留空自动判定

## 章节名

正文段落……
```

- 文件名以下划线开头的是参考资料，不参与导入
- 可反复执行，按题名归一化去重后更新

## 13. 评测

**功能**：量化检索质量与生成质量。

| 能力 | 说明 |
|------|------|
| 评测集生成 | 从文本块反向生成临床问题，强制同义改写防词汇泄漏 |
| 检索评测 | Recall@K、MRR、NDCG@K |
| 消融实验 | 逐项关闭检索路径或处理策略，比较指标变化 |
| 生成评测 | 忠实度、相关性、引用准确率（大模型裁判 + 数值核验） |
| 结果存档 | JSON 结果 + 汇总表 |

```bash
python -m app.eval.cli generate --language zh --target 150
python -m app.eval.cli stats

```
