核对发现 `PUB-PMC12187830` 的冻结摘录只包含 “Case presentation”，并发症经过位于同一 XML 的 “Diagnostic assessment”等相邻章节。本轮将额外章节纳入复核材料并明确标记，保留冻结病例原文，不直接以标题推断字段。数据库仍是 10 条草稿、0 条发布。

审核者应复制 JSON 后填写 `review` 内的姓名、日期、结构化字段、原文支持、许可确认、异议与决定。病例应通过现有病例编辑/管理员审核流程发布；本轮不提供跳过审核的批量发布命令。

复现：在 `backend` 目录执行 `python -m scripts.prepare_clinical_review`。每次创建新目录，避免覆盖人工填写结果；任何源文不一致都会中止。全程本地读取，不调用外部生成模型。

## 文献页码、原文与历史引用保全

- PDF 物理页码现在通过解析条目、小节、切块传到 `page_start/page_end`，空白页不会导致后续页码前移。标题块不伪造页码；DOCX/Markdown 不推算分页。已有入库块不批量猜填历史页码，PDF 物理页序也不冒充期刊印刷页码。
- 全无文字层的 PDF 继续明确提示 OCR；混合 PDF 的无文字页、低文字量页新增提醒，预览 CLI 和入库标注说明均保留提醒。提醒不能替代 OCR 或图表识别。
- 任意 PDF 不再自动赋予指南证据等级，默认 `other`；正式等级需来源依据或人工声明。现有数据库等级不在本轮批量改写。
- 本地导入原文件按内容 SHA256 保存在 `data/document_sources/`，不随编辑原始路径而覆盖；解析时与入库前的哈希不一致会拒绝入库。快照目录不参与手工导入扫描。
- 新表 `kb_chunk_revision` 在真实修订前保存旧文本、旧题名/期刊/年份、页码、分类、来源文件摘要等。旧块从活动检索表删除，历史快照不参与新问题的召回及统计；`/api/chunks/{旧ID}` 仍可返回原文并标记 `archived`。
- 相同正文、分块和元数据重复导入会跳过，保留原 ID，不制造新版本。真实修订清除旧审核人/审核标记，要求重新核对；保留原有上架设置，未改全局审核策略。
- 每篇文章使用独立保存点。修订失败时归档和替换一起回滚，批次中失败文章不撤销之前成功文章。向量化列表排除同批内被替换的旧块。
- 管理页面新增历史证据入口与物理页码标签，医师可看详情；引用面板展开旧块时显示“历史版本原文”。彻底删除文献会连同历史块一起删除，不绕过现有彻底删除语义；下架保留证据。

历史保全从本次更新后的修订开始生效，无法凭空恢复先前已经删除的文本块。原文件只读保存用于溯源，不等于授予下载或再分发许可。

复现：

```powershell

python -m scripts.preview_document 'D:\资料\文献.pdf'  # 只解析预览，不入库
python -m scripts.verify_document_versions          # 独立临时数据库，不改正式语料
python -m scripts.sync_schema --dry-run
```

## 独立问答与影像标注准备

`data/reviews/20261105T040744206375Z/independent_annotation.json` 预留 20 个文献来源组，排除已有开发题的来源组。分组按 DOI、PMID、归一化题名做传递合并后再划分，记录全部候选正文和摘要值。没有自动生成题目或正例标签，也没有输出新的效果分数。

现有开发过程已看过语料，且 DOI/题名之外仍可能有重复版本，因此这只是未标注的来源预留，不能声称已经构建独立临床留出集。需由独立出题者在不看检索排名的条件下出题、多正例标注，再冻结标签；来源版本重复关系需人工补核。

同份材料包含 3 张影像的本地登记及 3 组两两配对空表，保留来源、许可、脱敏确认、来源分组与双人标注/分歧处理栏位。没有把三张影像硬划成可用的训练/测试集，也没有将颜色分数当作临床标签。准备更多有明确来源及授权的影像后，再按病例/原文来源分组、留出并比较编码器。没有下载新模型或外发影像。

复现：`python -m scripts.prepare_independent_annotation`。每次另建目录，原人工标注不覆盖。
