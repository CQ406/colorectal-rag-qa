# 启动与关闭 · 操作速查

> 项目路径：`D:\AI\RAG_project`
> 三个数据库跑在 Docker 里，后端与前端跑在 Windows 上。

---

## 一、下次怎么打开（完整步骤）

### 方式 A：一键启动（推荐日常使用）

1. 打开文件资源管理器，进入 `D:\AI\RAG_project`
2. **双击 `start.bat`**
3. 等 1~3 分钟，看到浏览器自动打开 `http://127.0.0.1:5173`

**`start-all.ps1` 会自动做这 5 件事**：

| 步骤 | 内容 |
|------|------|
| 1 | 检查并启动 Docker 容器（PostgreSQL / Neo4j / Redis） |
| 2 | 预热检索模型（BGE-M3 + 重排模型，首次约 60 秒） |
| 3 | 启动后端 FastAPI（端口 8000） |
| 4 | 启动前端 Vite（端口 5173） |
| 5 | 打开浏览器 |

> **首次启动慢是正常的**：模型要从磁盘加载到显存，约 60 秒。
> 之后启动会快很多。

### 方式 B：分步启动（写论文/调试时用）

```powershell
# ① 启动数据库容器
cd D:\AI\RAG_project
docker compose up -d

# ② 启动后端（新开一个终端窗口）
cd D:\AI\RAG_project\backend
$env:PYTHONPATH="D:\AI\RAG_project\backend"
& "D:\deep seek test\rag-venv\Scripts\python.exe" -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload

# ③ 启动前端（再开一个终端窗口）
cd D:\AI\RAG_project\frontend
npm run dev
```

然后浏览器打开 **http://127.0.0.1:5173**

### 方式 C：VS Code 调试（要打断点时用）

1. VS Code 打开 `D:\AI\RAG_project\rag-project.code-workspace`
2. 按 **`F5`** → 选 **「▶ 启动后端 (FastAPI)」**
3. 前端另开终端跑 `npm run dev`，或在 VS Code 里按 `F5` 选「启动前端」

> ⚠️ **方式 A/B/C 三选一**，不要同时用。后端只能有一个进程占用 8000 端口。

## 二、现在怎么关闭（完整步骤）

### 第 1 步：关闭后端与前端

**双击 `D:\AI\RAG_project\stop.bat`**

它会自动：
- 按端口（8000 / 5173）找到进程并停止
- 清理可能残留的 uvicorn 子进程
- 停止三个 Docker 容器
- 验证端口已释放

> **为什么用 `stop` 而不是 `down`**：`stop` 只停容器、**保留数据和容器定义**，
> 下次启动更快。`down` 会删除容器（数据仍在命名卷里，但重建较慢）。

### 第 2 步：关闭 VS Code

直接关窗口即可。**它会自动结束自己的 Python 语言服务和调试适配器**，不用手动处理。

> ⚠️ 如果你是在 VS Code 里按 F5 启动的后端，
> 关 VS Code 时它会弹窗问是否停止调试会话 —— 选**停止**。

### 第 3 步（可选）：完全退出 Docker Desktop

如果你想让 Docker 也不占内存：

- 右下角系统托盘 → 右键 Docker 图标 → **Quit Docker Desktop**

> 这一步**不是必须的**。容器已停，Docker Desktop 只占约 200~400 MB。
> 而且退出后下次启动要重新等 Docker 引擎起来（约 30 秒）。

## 三、怎么确认真的关干净了

在任意终端跑这条：

```powershell
# 检查应用端口（应无输出）
Get-NetTCPConnection -LocalPort 8000,5173 -State Listen -ErrorAction SilentlyContinue

# 检查容器（应全部 Exited）
docker ps --filter "name=cr-"
```

**期望结果**：
- 端口查询无输出
- 三个容器显示 `Exited`

## 四、常见问题

### Q1：按 F5 报 `WinError 10013`

**原因**：已有一个后端在占用 8000 端口（可能来自 `start.bat` 或上一次调试）。

**解决**：
```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

### Q2：浏览器打开是空白 / 报错连不上后端

**检查顺序**：
1. 后端起来了吗？浏览器访问 http://127.0.0.1:8000/api/health
   - 看到 JSON（含 `components` 数组）→ 后端正常
   - 连接失败 → 后端没起来，重跑 start.bat
2. 前端起来了吗？访问 http://127.0.0.1:5173
3. 数据库起来了吗？`docker ps` 看三个容器是否 `Up (healthy)`

### Q3：问答应答很慢（首字十几秒）

**正常现象**。首次提问会触发模型冷加载（约 60 秒），之后降到 3~5 秒。

**想更快**：先访问一次后端预热接口
```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/models/load
```

### Q4：影像解读报「未配置视觉模型密钥」

检查 `D:\AI\RAG_project\.env` 里的 `VLM_API_KEY` 是否填写。
改完 `.env` **必须重启后端**才生效。

### Q5：改了代码要重启吗

| 改动位置 | 是否需要重启 |
|---------|------------|
| 后端 `backend/app/**.py` | 后端带 `--reload` 会自动重载；否则需重启 |
| 前端 `frontend/src/**` | **不用**，Vite 有热更新 |
| `.env` 配置 | **必须重启后端** |
| `docker-compose.yml` | 需 `docker compose up -d` 重建 |

## 五、文件说明

| 文件 | 用途 |
|------|------|
| `start.bat` | **一键启动**（双击） |
