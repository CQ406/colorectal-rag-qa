| 历史影像没有向量、检索候选为空 | 增加可预览、可重复执行的特征补算脚本 | 先预览数量，再应用补算，检查向量数量及相似接口 |

| 影像引用弹窗拼接文献标题 HTML | 改为文本节点渲染引用元数据 | Vue 类型检查及构建 |

草稿工作区沿用现有病例库的角色共享规则：有维护权限的医师可查看和编辑未发布内容，
不是按上传者隔离。如果将来开放给不同团队，应增加上传者、团队与数据范围字段再开放使用。

历史影像补算命令（在 backend 目录，使用项目 Python 环境）：

```powershell
python -m scripts.backfill_image_features          # 仅预览
python -m scripts.backfill_image_features --apply  # 仅为缺少特征的影像生成特征
```

脚本每批默认处理最多 100 张，可用 `--limit` 调整；当前版本特征不覆盖，未知或过期版本会重算，发布状态不修改。
丢失或损坏的原图会报失败并保留为空，不能把缺失原图当作正常向量入库。

### 病例与影像数据建议

首批样例重在覆盖不同流程和证据来源。每条记录至少包含病例标题、诊断、围术期阶段、
病史摘要、手术/处理记录、结局、原始出处及可公开依据。缺失信息明确标记“原文未报告”，
不为了填满表单而补写。来源、出处链接、整理者、审核人与审核记录现已增加，10 条文献摘录已导入为草稿。
临床字段尚未结构化时明确注明状态。演示合成数据只进入独立测试库，不混作真实研究材料。

当前病例编辑表单使用已发布影像选择器，API 也会拒绝不存在的影像链接，
并阻止公开病例关联未公开影像；病例详情可跳转到影像查看页。来源字段、审核意见与时间线已实现。

### 问答和评测建议

优先验证“找对证据”和“引用确实支持答案”。围绕术前评估、术中操作、术后并发症、
多轮追问及证据不足五类建立小规模人工复核集。既有自动生成评测可以保留作回归集，
但应另外设置人工核对的留出集，避免仅凭自动生成问答证明效果。

比较纯向量、向量加关键词、加入图谱、不带图谱的重排、图谱加重排五组配置，报告相同问题集上的结果。
耗时区分首次模型加载与预热后请求，分别记录首字延迟、完整回答耗时和 P50/P95。
五组检索对比已基于当前固定 12 题开发集执行，详见 [检索评测与复核报告](检索评测与复核报告.md)。生成答案的临床准确性、引用支持关系和独立留出验证仍需人工核对；工作表已准备在 [问答人工复核工作表](问答人工复核工作表.md)。目前不凭 12 题结果直接改变生产默认开关。

### 影像相似检索建议

现有 RGB 直方图只表达颜色分布，不编码解剖结构与诊断语义；相似百分比不能解释为诊断概率。
先完成样本和标注，再考虑视觉编码器升级。新编码器与旧特征即便维度一致也不能直接混用，
应增加编码器版本、维度和生成时间，安排独立重建与回滚步骤。
