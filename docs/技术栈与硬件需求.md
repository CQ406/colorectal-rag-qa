# 《基于术中影像与RAG的结直肠手术围术期多模态知识库智能问答系统》技术栈与硬件配置需求

> 依据课题报审表（`.doc` 版本，含 15 篇正式参考文献）中「主要参考内容」的实际功能需求整理，按**调研 → 设计 → 实现 → 测试 → 答辩**全流程给出可落地的选型。
>
> 课题原始范围将影像特征相似度检索列为拓展方向；本项目已补充实现 512 维颜色直方图基线与 pgvector 检索。图像理解仍调用云端多模态 API；GPU 用于本地向量模型加速，不是系统运行的硬性要求。

## 一、技术栈总览

| 层次 | 技术选型 | 作用 |
|------|----------|------|
| 前端 | Vue 3 + Vite + TypeScript + Element Plus | 问答、知识库管理、影像上传 |
| 后端 | Python 3.11 + FastAPI + Uvicorn + SQLAlchemy 2.0 + Pydantic v2 | 业务接口、流式问答、权限 |
| 数据库 | PostgreSQL 16 + pgvector（向量） | 元数据、向量、全文检索一体化 |
| 图数据库 | Neo4j 5 Community | 知识图谱：疾病-术式-并发症-药物 |
| 缓存 | Redis 7 | 会话上下文、检索结果缓存、限流 |
| 对象存储 | MinIO / 本地磁盘 | 原始 PDF、Word、影像文件 |
| 文献采集 | requests + PubMed E-utilities + Scrapy | 自动采集与增量更新 |
| 文档解析 | PyMuPDF / pdfplumber + MinerU（复杂版面/表格）+ python-docx | PDF/Word 结构化 |
| OCR | PaddleOCR / RapidOCR；备选智谱 OCR API | 扫描版文献与图表文字 |
| 文本切分 | 项目现有解析、分块与元数据逻辑 | 本轮迁移只更改 RAG 编排，不重切语料 |
| Embedding | **BGE-M3**（dense + sparse + colbert 多向量） | 中文/英文医学术语检索 |
| 向量检索 | pgvector HNSW + PG 全文检索（BM25 近似）+ RRF 融合 | 多路召回 |
| 重排 | bge-reranker-v2-m3 | 精排，提升 Top-K 准确率 |
| 大语言模型 | **DeepSeek-V3 / DeepSeek-R1**（API）；本地备选 Qwen3-8B-Instruct | 答案生成、意图理解 |
| 多模态大模型 | **GLM-4V-Flash**（免费图像理解）或 qwen-vl-plus / qwen3-vl-plus | 术中影像解读 |
| 图谱抽取 | LLM 结构化输出（JSON Schema）+ 规则后处理；可选 MC-BERT / Chinese-RoBERTa 微调 | 实体识别与关系抽取 |
| 医学视觉特征升级（规划） | BiomedCLIP / 通用 CLIP + pgvector | 在现有颜色直方图检索基础上升级医学语义特征 |
| 编排 | LangChain LCEL（langchain-core 1.7.6） | 主问答与多轮问答共用检索增强生成链；会话持久化由现有数据库服务负责 |
| 可观测与评测 | Langfuse（链路追踪）+ RAGAS（忠实度/相关性）+ 自建 150 题评测集 | 效果量化、论文实验数据 |
| 任务调度 | Celery + Redis，或 APScheduler | 文献批量入库、索引重建 |
| 标注工具 | doccano / Label Studio（LLM 预标注 + 人工校对） | 评测集与微调数据 |
| 部署 | Docker + Docker Compose；GPU 推理可选 vLLM | 一键环境、答辩演示 |
| 版本管理 | Git + DVC（数据集/模型版本）+ Alembic（库结构迁移） | 可复现、可回溯 |
| 测试 | pytest + httpx + Locust（压测） | 接口与性能测试 |

### 关键选型的说明

1. **向量库选 pgvector 而不是 Milvus**：Milvus 依赖 etcd + MinIO + Pulsar，单机部署重、调试成本高。本课题知识规模（约 5 千～2 万篇文献、20 万级文本块）用 pgvector 的 HNSW 索引完全够用，且向量、元数据、全文检索在同一事务里，做「多路召回 + RRF 融合」时 SQL 一次写完，论文里也更好讲清架构。若后期要展示向量库运维能力，再迁 Qdrant（单容器、更轻）或 Milvus。
2. **Embedding 用 BGE-M3 而不是调云端 API**：一个模型同时输出稠密向量、稀疏权重和多向量表示，规避了"两套模型两套索引"；权重仅约 2.2GB，笔记本或 4GB 显存即可跑。语料含大量中文指南与英文文献，BGE-M3 的中英混合表现是当前开源里的稳妥选择（[BGE-M3 显存占用讨论](https://huggingface.co/BAAI/bge-m3/discussions/64)）。
3. **影像解读走云端 API，不做本地视觉模型训练**：项目已实现颜色直方图基线相似检索；该特征不等同于医学语义视觉模型，后续可升级。智谱 **GLM-4V-Flash**（[官方文档](https://docs.bigmodel.cn/cn/guide/models/free/glm-4v-flash)）支持图像理解，也可切换[通义千问 VL 系列](https://help.aliyun.com/zh/model-studio/what-is-qwen-llm)。**模型输出仅作教学参考，不作为诊断依据**。
4. **知识图谱用 Neo4j Community + 显式路径推理**：报审表要求的是"疾病、术式、并发症、药物等实体的语义关联"和小规模图谱推理检索。Cypher 显式查询（如"该术式常见并发症及其处理药物"）比图嵌入更可控、可解释，也更容易在论文中做案例分析。
5. **不要把 LangChain 当架构**：多路召回、RRF 融合、重排、引用溯源这段核心逻辑建议手写，LangChain LCEL 用于显式串联检索、证据门控、提示词、生成与校验阶段。这样答辩时每一个检索决策都能讲明白，也避免框架版本变更导致演示崩掉。

## 二、硬件配置需求

### 2.1 核心结论

本课题**默认不需要 GPU**：影像理解走云端 API、向量模型只有 2.2GB、生成走 DeepSeek API。一台 16GB 内存的普通笔记本 + 联网 + 约 50 元/月的 API 费用即可完成全部开发与答辩演示。

GPU 只有在需要"本地化部署大模型"（医院数据不出内网的合规叙事、或论文要体现工程部署能力）时才需要。三条档位如下。

### 2.2 三档硬件方案

#### 方案 A：开发演示档（推荐起步，零 GPU 投入）

| 项目 | 配置要求 |
|------|----------|
| CPU | 4 核 8 线程以上（i5-1135G7 / R7-5800H 同级即可） |
| 内存 | **16GB（最低）**，建议 32GB |
| 硬盘 | 512GB SSD，**可用空间 ≥ 100GB** |
| 显卡 | 不需要独立显卡（BGE-M3 用 CPU 推理，单条 embedding 约 50～200ms） |
| 网络 | 稳定 ≥ 20Mbps，需能访问 DeepSeek / 智谱 / PubMed 接口 |
| 系统 | Windows 10/11 或 Ubuntu 22.04（WSL2 + Docker Desktop） |
| 成本 | 0 元硬件新增 + API 费用约 **30～80 元/月** |

**这是最省事的路线。** 唯一代价是：文献批量入库时 embedding 全量跑一次约需 1～3 小时（20 万块），可放后台过夜执行。

#### 方案 B：本地推理档（能跑本地大模型，答辩亮点足）

| 项目 | 配置要求 |
|------|----------|
| CPU | 8 核 16 线程以上（i7-13700 / R7-7800X3D 同级） |
| 内存 | **32GB**（本地 8B 模型 + 向量库 + Docker 同时运行的基本盘） |
| 显卡 | **RTX 4060 Ti 16GB** 或 RTX 4070 Ti SUPER 16GB；最低 RTX 3060 12GB |
| 硬盘 | 1TB NVMe SSD（模型权重就占 5～20GB） |
| 电源 | 650W 以上（台式机） |
| 成本 | 整机约 **8000～12000 元**（已有笔记本则单配 eGPU/台式主机约 6000～8000 元） |

可承载：BGE-M3 + reranker（约 4～6GB）+ Qwen3-8B-Instruct 4bit 量化（约 6～7GB）——总计 12GB 左右可跑通，回答速度约 20～40 token/s，够答辩演示。

#### 方案 C：本地完整部署档（数据不出内网的完整叙事）

| 项目 | 配置要求 |
|------|----------|
| CPU | 16 核以上（Xeon / Threadripper 或 i9） |
| 内存 | **64GB** |
| 显卡 | **RTX 4090 24GB** 或 2× RTX 4090 / A6000 48GB |
| 硬盘 | 2TB NVMe SSD（RAID 1 更稳） |
| 成本 | 约 **25000～45000 元**（或租云 GPU，见 2.4） |

可承载：Qwen3-14B/32B 4bit 量化 + BGE-M3 + reranker + vLLM 并发 10～20 路。适合论文里写"私有化部署方案"，或院方提供真实数据时的场景。

### 2.3 显存（VRAM）需求明细

以下为 fp16/4bit 推理的工程估算，含模型权重、激活与 KV cache，均假设上下文 8K、并发 1～4 路：

| 组件 | 权重占用 | 建议最低显存 | 备注 |
|------|----------|--------------|------|
| BGE-M3 embedding | ≈ 2.2GB | 4GB | 可 CPU 运行，速度慢 3～5 倍 |
| bge-reranker-v2-m3 | ≈ 2.2GB | 4GB | 精排，与 embedding 可共用同一张卡 |
| Qwen3-8B-Instruct（4bit AWQ/GPTQ） | ≈ 6～7GB | 10～12GB | 长文档问答建议 16GB |
| Qwen3-14B（4bit） | ≈ 11GB | 16～20GB | — |
| Qwen3-32B（4bit） | ≈ 20～22GB | 24GB+ | 需 4090 级别 |
| Qwen2.5-VL-7B（本地多模态备选） | ≈ 16GB（fp16） | 24GB | 建议仍用云端 API 替代 |
| vLLM 服务开销 | +1～2GB | — | 并发数增加需额外 KV cache |

**关键提醒**：显存不是唯一瓶颈。本地跑 8B 模型时，**内存 32GB 是硬门槛**（Docker + PostgreSQL + Neo4j + Redis + 模型加载峰值），16GB 内存会在索引重建时被 OOM Killer 杀掉进程。

### 2.4 存储与网络需求

| 类型 | 估算 | 说明 |
|------|------|------|
| 原始文献（PDF/Word） | 100～400GB | 按 1 万篇、每篇 10～40MB 计；建议按年份/期刊分目录 |
| 结构化文本与元数据 | 2～5GB | PostgreSQL 中的 chunk、题录、标注 |
| 向量索引 | < 1GB | 20 万 × 1024 维 float32 ≈ 0.8GB（pgvector） |
| 知识图谱 | 1～2GB | Neo4j 图数据（实体量 10 万级） |
| 影像资料 | 5～50GB | 公开样例影像；若含 DICOM 序列会显著增长 |
| 模型权重 | 5～20GB | BGE-M3 + reranker + 本地 LLM |
| Docker 镜像 | 15～25GB | PostgreSQL/Neo4j/Redis/MinIO/vLLM 镜像合计 |
| **建议预留** | **≥ 500GB，推荐 1TB SSD** | — |

**网络带宽**：首次拉取模型与 Docker 镜像需下载 20～40GB，建议 50Mbps 以上；日常 API 调用流量极小（约 100k token/天 ≈ 数 MB）。**注意**：医院或校园内网可能屏蔽 PubMed 与部分 API 域名，需提前在开题阶段验证网络可达性，否则改用镜像源或离线文献包。

### 2.5 云端 API 与成本估算

| 用途 | 推荐服务 | 计费参考 | 月成本估算 |
|------|----------|----------|------------|
| 答案生成 / 意图理解 | DeepSeek API | 输入约 ¥0.5～2/百万 token，输出约 ¥8～16/百万 token（优惠期后输出约 8 元/百万 token，见[报道](https://www.cnstock.com/commonDetail/358139)） | ¥20～60 |
| 影像理解 | GLM-4V-Flash | **完全免费**（[官方文档](https://docs.bigmodel.cn/cn/guide/models/free/glm-4v-flash)） | ¥0 |
| 影像理解（备选，更强） | qwen-vl-plus / qwen3-vl-plus | 按输入 Token 阶梯计费（[百炼定价说明](https://help.aliyun.com/zh/model-studio/what-is-qwen-llm)） | ¥10～50 |
| Embedding | BGE-M3 本地 | 免费（吃 CPU 或显存） | ¥0 |
| 重排 | bge-reranker-v2-m3 本地 | 免费 | ¥0 |
| 图谱抽取 | DeepSeek API 批量跑一次 | 约 ¥10～50 一次性 | — |
| 云 GPU（方案 C 替代） | 按需租用 4090/A100 | 约 ¥2～10/小时 | 演示阶段 ¥100～300 |

**总成本**：方案 A 约 **¥30～100/月**；方案 B/C 为硬件一次性投入，日常电费与 API 费用基本可忽略。

## 五、环境搭建清单（可直接照做）

```bash
# 基础环境
Python 3.11 + Node.js 20 LTS + Docker Desktop + Git

# 后端依赖
pip install fastapi uvicorn[standard] pydantic sqlalchemy alembic psycopg[binary] pgvector
pip install -r backend/requirements.txt
pip install FlagEmbedding sentence-transformers transformers torch  # BGE-M3 / reranker
pip install neo4j redis minio python-jose passlib[bcrypt] httpx

# 评测与追踪
pip install ragas langfuse

# 前端
npm create vite@latest web -- --template vue-ts
npm i element-plus pinia vue-router axios echarts pdfjs-dist

# 服务编排
docker compose up -d postgres neo4j redis minio
```

**建议的数据库初始化**：

```sql
CREATE EXTENSION vector;
CREATE INDEX ON kb_chunk USING hnsw (embedding vector_cosine_ops);
-- 中文全文检索需 zhparser 或 pg_bigm 扩展，否则用 pgvector 内建分词替代
```

| 阶段 | 周期 | 交付物 |

## 六、风险与注意事项

1. **合规红线**：只能使用公开文献与公开脱敏影像。**不要接入真实患者数据**，除非已完成伦理审查与数据脱敏。系统和论文均需声明"辅助参考，不构成诊疗建议"。
2. **中文文献版权**：CNKI 等数据库有反爬与版权限制，建议优先用 PubMed、arXiv、中华医学会公开指南，或使用学校已购数据库的合规导出功能。
3. **CNKI 抓取风险**：如需抓取，控制频率、遵守 robots.txt，避免给学校 IP 带来封禁风险。
4. **本地小模型的幻觉**：8B 量化模型在医学问答上幻觉率明显高于云端大模型。若答辩现场无网络，需提前把演示题目缓存好，或写清"演示模式使用缓存结果"。
5. **嵌入模型维度与索引一致性**：全量重建索引时必须保证模型版本、维度、归一化方式三者一致，否则检索结果会静默劣化。建议在数据库里记录 embedding 模型版本号。
6. **评测集必须自建，并可直接对标报审表参考文献**：RAGAS 只能给相对指标，答辩时最有说服力的是自己标注的 150～200 道结直肠围术期问题（含标准答案与正确来源段落），报告 Recall@K、MRR、忠实度、引用准确率。报审表已列出的三篇文献正好构成评测与校准的方法学依据，建议在论文实验中直接引用：
   - **[13] Xiong G, et al. Benchmarking retrieval-augmented generation for medicine**（arXiv:2402.13178）——医学 RAG 基准测试方法，可参照其指标设计自己的评测维度；
   - **[10] Liu S, McCoy AB, Wright A. Improving LLM applications in biomedicine with RAG**（JAMIA 2025）——RAG 在生物医学中的系统评价与**临床开发指南**，可作为系统设计与合规声明的直接依据；
   - **[12] Savage T, et al. LLM uncertainty proxies: discrimination and calibration for medical diagnosis and treatment**（JAMIA 2025）——模型置信度校准，用于回答"系统输出是否可靠、如何提示不确定性"这一必问点。
7. **显存与内存的取舍**：若只有 8GB 显存，优先保证 embedding + reranker 在 GPU 上、生成走 API；反过来（生成本地、检索 CPU）会显著拖慢响应。
8. **首次 embedding 全量耗时**：CPU 跑 20 万块约 1～3 小时，务必用 Celery 后台任务 + 断点续跑，别写成同步请求。

## 七、最简可行配置（如果只想要一句话结论）

- **技术栈**：Python 3.11 + FastAPI + Vue 3 + PostgreSQL/pgvector + BGE-M3 + bge-reranker-v2-m3 + DeepSeek API + GLM-4V-Flash（影像，免费）+ Neo4j（图谱）+ Docker Compose。
- **硬件**：普通笔记本（16GB 内存、512GB SSD、无需独显）；想本地跑模型则 32GB 内存 + RTX 4060 Ti 16GB 及以上。
- **月成本**：约 30～100 元 API 费用，其余全部开源免费。

> **本机适配说明**：现有开发机（Ryzen 9 8945HX / 32GB / RTX 5060 8GB）的实测评估与微调方案见
> [本机硬件适配-技术栈微调方案.md](本机硬件适配-技术栈微调方案.md)。
> 结论是：**该机器无需追加硬件即可完成本课题**，采用"GPU 跑检索模型 + 大模型走 API"的混合方案；
> 但有两个必须处理的点——**PyTorch 必须装 cu128 版本**（RTX 5060 是 Blackwell 架构），以及
> **C 盘仅剩 68.8GB，需先把 Docker 数据与模型权重迁到 D 盘**。
