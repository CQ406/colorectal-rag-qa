## 数据边界

10 条记录是来自公开文献的病例章节摘录草稿，不能称作已经完成临床字段结构化或专家审核的病例。不会补写原文未报告的患者信息，也没有为凑齐关联关系而虚构病例与影像匹配。公开病例数量仍为 0，因此当前病例推荐没有公开候选是预期状态。来源见 [公开病例来源目录](公开病例来源目录.md)。

图谱 1556 节点/1500 关系是总规模，当前有效来源覆盖只有 23 个文本块，不能当成完整覆盖 3772 块。图谱维护 API/脚本写入后发布本地更新标记，使同一项目目录下运行的 API 自动重新核对实体索引；绕过应用直接修改 Neo4j 后仍需重启 API 或显式刷新索引。

依赖约束、模型配置和启动步骤已记录，但没有在全新机器上安装验证。当前服务为本机开发运行，不能称作生产部署验收完成。操作步骤见 [启动与备份恢复手册](启动与备份恢复手册.md)。

## 下一轮建议顺序

1. 先整理及人工审核 10 条病例草稿，逐题完成 12 题问答的引用支持、适用人群、数值与拒答复核。明确记录审核人、日期及异议；只有通过审核的病例才发布。
2. 建立独立留出集和多相关证据标注，再确认检索默认策略。当前开发集优先考虑融合＋重排；图谱暂用于可追溯关系查询，不凭小样本成绩宣称增益。
3. 补文献解析质量与版本管理：扫描件/OCR 提示、解析预览、页码保全、修订版本及旧引用定位。优先避免证据进入知识库后失去来源。
4. 准备有授权的临床影像和独立相似标注，再比较视觉编码器；按来源隔离开发/留出集，记录特征版本，保留回滚索引。
5. 用全新环境复现安装与恢复，落实迁移历史、HTTPS、反向代理、正式进程管理及监控，再开放对外访问。
