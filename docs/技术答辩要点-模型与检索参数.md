## 1. Embedding 模型与向量库

### 1.1 模型

| 项 | 值 |
|---|---|
| 文本嵌入 | **BGE-M3**（本地权重 `D:\models\bge-m3`） |
| 向量维度 | **1024** |
| 推理精度 / 设备 | fp16 / CUDA（RTX 5060 Laptop 8GB） |
| 推理批大小 | 32 |
| 重排模型 | **bge-reranker-v2-m3**（交叉编码器） |
| 视觉模型 | 智谱 **GLM-4V-Flash**（OpenAI 兼容接口） |
| 文本生成 | DeepSeek（OpenAI 兼容客户端，可切 GLM） |

### 1.2 向量库

**没有使用独立向量库**（未用 Milvus / Qdrant / Chroma / FAISS），
而是 **pgvector 0.8.7** 作为 PostgreSQL 16 的扩展：

```sql
-- 向量列
kb_chunk.embedding  vector(1024)

-- 索引：HNSW + 余弦距离
CREATE INDEX ix_chunk_embedding_hnsw
  ON kb_chunk USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);

-- 中文关键词倒排：bigram 存 text[]，GIN 索引
kb_chunk.bigrams  text[]
CREATE INDEX ... USING gin (bigrams);
```

**选型理由**：文本元数据（分期、证据等级、语言、文献来源）、1024 维向量、
中文 bigram 倒排索引放在同一个库里，混合检索与元数据过滤能写进一条 SQL，
不需要跨库 JOIN 或二次过滤。对 4 千块体量，HNSW 查询在毫秒级，没有引入
独立向量库的必要。

**复核**：

```powershell
docker exec cr-postgres psql -U rag -d colorectal_rag -c "SELECT extname, extversion FROM pg_extension WHERE extname='vector';"
docker exec cr-postgres psql -U rag -d colorectal_rag -t -c "SELECT indexdef FROM pg_indexes WHERE indexname='ix_chunk_embedding_hnsw';"
```

## 2. 文本切块：大小、重叠与依据

### 2.1 参数

| 参数 | 值 | 代码位置 |
|---|---|---|
| 单块上限 | **512 token** | `chunker.py: DEFAULT_MAX_TOKENS = settings.model.embedding_max_length` |
| 相邻重叠 | **64 token**（约 1/8） | `chunker.py: DEFAULT_OVERLAP_TOKENS = 64` |
| 切分顺序 | 先按章节（`##` 小节）分域，再按句子贪心聚合 | `chunker.py::build_chunks` |

### 2.2 实测分布（4,348 块）

| 指标 | 数值 |
|---|---|
| 平均 | 424 token / 1,165 字符 |
| 中位 | 842 字符 |
| 最大 | 685 token / 2,743 字符 |

### 2.3 依据（如实表述）

1. **512 的依据是模型配置长度 + 检索粒度折中**：BGE-M3 本身支持更长输入，
   但块过长会让"一个块里混进多个主题"，向量表征被平均掉、检索命中变模糊；
   512 能在"上下文完整"与"主题单一"之间取平衡。
2. **64 token 重叠**用于接续跨块上下文，避免答案正好被切在边界上导致
   两侧都只看到半个结论。
3. **先按章节再按句子**，是因为指南类文献的章节结构本身携带语义边界，
   比纯长度切分更贴近"一个块 = 一个可引用论断"的目标。

> ⚠ **方法学缺口（答辩时应主动说明）**
> 以上是经验折中，**未做 chunk size 的对照实验**（如 256 / 512 / 768 各跑一遍
> 50 题评测集）。因此"512 最优"目前没有实验支撑，只能说"未发现明显问题"。
> 若要补：约 1 小时可完成三档对照。

**复核**：

```powershell
docker exec cr-postgres psql -U rag -d colorectal_rag -c "SELECT round(avg(char_count)) 平均字符, percentile_disc(0.5) WITHIN GROUP (ORDER BY char_count) 中位字符, max(char_count) 最大字符, round(avg(token_count)) 平均token, max(token_count) 最大token, count(*) 块数 FROM kb_chunk;"
```

## 3. 混合召回：**三路**，不是两路

### 3.1 三路召回

| 路 | 实现 | 取数上限 |
|---|---|---:|
| ① 向量语义 | pgvector HNSW 余弦相似 | Top 50 |
| ② 关键词 | **中文 bigram** 倒排（`text[]` + GIN），覆盖率 ≥ 0.3 过滤 | Top 50 |
| ③ 知识图谱 | Neo4j 实体邻接 → 映射回文本块 | Top 20 |

### 3.2 融合方式：RRF（倒数排名融合）

$$\text{score}(d)=\sum_{i}\frac{w_i}{k+\text{rank}_i(d)},\quad k=60$$

| 权重 | 值 | 依据（均有实测支撑） |
|---|---:|---|
| 向量 `vector_weight` | **1.0** | 主力召回 |
| 关键词 `keyword_weight` | **0.3** | 单独使用时中文 R@5 ≈ 0.000：口语提问与学术文本词汇体系不同，bigram 是精确词元匹配，跨不过"这两个术式有什么区别"到"robotic versus laparoscopic"的表述差异。降到 0.3 后融合不再劣化；保留它只为精确术语命中（ICG、taTME、ERAS 等缩写）。 |
| 图谱 `graph_weight` | **0.2** | 曾设 0.6，实测发现图谱边连到"疾病—症状"这类泛化实体，会引入游离块并互相提权，MRR 从 0.542 掉到 0.340。降至 0.2 并把图扩到覆盖 20.7% 语料后，MRR 回到 0.558。 |

融合后：截断 80 条候选 → **交叉编码器重排** → 单篇文献最多保留 3 块 →
取 top_k（默认 5）。

### 3.3 消融实测（50 题集）

| 配置 | R@5 | R@10 | MRR@10 |
|---|---:|---:|---:|
| 三路融合（无重排） | 0.780 | 0.820 | 0.557 |
| **三路融合 + 重排** | **0.800** | **0.860** | **0.666** |

**重排贡献最大**（MRR +0.109）。图谱在所有配置下**没有带来稳定增益**——
这是本项目的负结果，已如实记录，不宣称"图谱提升了效果"。


## 4. 影像处理（重点）

### 4.1 先把边界划清

**不做**：不做病灶分割、不做影像分类识别、不做影像诊断。

**做**：元数据标引 + 图文检索 + 视觉模型的客观描述 + 结合文献的辅助解读。

这个定位决定了系统不会输出"这张图是 T3 期肿瘤"这类它无法负责的判断。

### 4.2 处理链路

| 步 | 内容 | 关键约束 |
|---|---|---|
| ① 上传入库 | JPG/PNG/WebP/BMP，≤ 8MB；**SHA256 去重**（重复上传复用已有记录）；存本地文件 | 记录宽高、术式、解剖部位、围术期分期、来源、公开状态 |
| ② 客观描述 | 调 GLM-4V-Flash（免费；该模型 max_tokens 硬上限 **1024**，超限直接 400） | 提示词**强制只描述所见、禁止下诊断结论**；结果缓存到 `vlm_analysis`，不重复计费 |
| ③ 构造检索查询 | 把②的描述文本当作 query | 走与文本问答**完全相同**的三路召回 + RRF + 重排 |
| ④ 综合解读 | LLM 基于检索到的证据生成解读 | 结论必须标 `[n]`；走**引用编号校验 + 数值核验**（与文本问答同一套） |
| ⑤ 落库快照 | 完整解读存 `vlm_interpretation` (JSONB) | 解读失败（`analysis.error` 非空）**不落库**，避免用"生成失败"文案覆盖此前成功结果 |

### 4.3 相似影像检索（拓展功能）

| 项 | 实现 |
|---|---|
| 特征 | **512 维 RGB 8×8×8 颜色直方图**，L2 归一化 |
| 版本标识 | `histogram-rgb8-v1` |
| 相似度 | 余弦 |
| 字段 | `feature_vector`（预留，将来换影像嵌入模型） |

**必须主动说明**：这只是**颜色基线特征**，不是医学语义特征。它能找到
"色调/构图相近"的图，但对"同一术式的不同解剖视角"没有区分力。

### 4.4 风险与兜底

| 风险 | 现状 |
|---|---|
| 视觉模型描述错误会传导到后续检索 | 无法自动纠正；但证据不足时系统会回"证据不足"而非顺着编 |
| 医学影像的专业描述超出通用 VLM 能力 | 已在提示词中限制为"只描述所见"，把诊断责任推回给医师 |
| 影像库样本量小（当前 3 张） | 相似检索与量化评估都不足，属演示级 |
| 影像解读的评价 | 未建独立评测集，只有功能验证 |

**复核**：

```powershell
curl -X POST http://127.0.0.1:8010/api/images/analyze -H "Content-Type: application/json" -H "Authorization: Bearer <token>" -d "{\"image_id\":\"<id>\",\"top_k\":5,\"use_cache\":true}"
```

## 5. 评测集与指标

### 5.1 评测集构成（v2，现行）

| 维度 | 分布 |
|---|---|
| 题量 | **50** |
| 题型 | 指南/共识类 20、综述/研究类 20、**关系型 10** |
| 语言 | **中文 50 / 英文 0**（全部中文） |
| 分期 | general 40、intraop 8、postop 2 |
| 标注方式 | 每题标注金标准块（`gold_chunk_ids`）、原文片段、页码 |
| 专家复核状态 | **尚未独立临床复核**（50 题全为 `pending_independent_clinical_review`） |

关系型题示例：

> 局部进展期直肠癌的长程放化疗、短程放疗和 TNT 模式，各自是什么关系？

设计意图：前 40 题考"能否找到对的那块"，后 10 题考"能否把多篇文献的关系串起来"。

### 5.2 三项指标（top_k = 10，语料 120 篇 / 4,348 块）

| 配置 | R@5 | R@10 | MRR@10 | 平均耗时 |
|---|---:|---:|---:|---:|
| 三路融合（无重排） | 0.780 | 0.820 | 0.557 | 1.41 s |
| **三路融合 + 重排** | **0.800** | **0.860** | **0.666** | 3.95 s |

金标准块校验：**50/50 有效，失效 0**。

### 5.3 与旧集（v1，12 题）的关系

| 集 | 题量 | R@5 | R@10 | MRR |
|---|---:|---:|---:|---:|
| v1 | 12 | 0.917 | 0.917 | 0.742 |

**两套不可横向比较**：v1 题目更短更直接、语料仅 109 篇，且后来因补语料重建过切块，
v1 的金标准已失效，仅作历史记录保留。**论文与答辩统一引用 v2 的 50 题数字。**

### 5.4 局限（必须说明）

1. **无专家复核**：50 题由构建者按原文标注单正例（single-positive），
   未经临床专家独立标注，不能据此宣称临床准确性。
2. **单正例标注**：只标"最佳那一块"，其余相关块记为不相关，R@5 会被低估。
3. **全中文**：英文文献虽占 1/3，但题干全中文，跨语言检索能力未被单独评估。
4. **评测集与调参集未严格分离**：部分参数是在同一批语料上迭代的，存在过拟合风险。

## 7. 口头答辩速答版（一句话）

| 问题 | 一句话回答 |
|---|---|
| 用什么 embedding | BGE-M3，1024 维，本地 GPU 跑 |
| 用什么向量库 | 没用独立库，用 pgvector 扩展挂在 PostgreSQL 里，HNSW 余弦索引 |
| 切块多大 | 512 token、重叠 64，按章节+句子切；实测平均 424 token |
| 为什么这么切 | 模型长度与检索粒度折中，**没做过对照实验**，是本次的一个缺口 |
| 混合召回几路 | 三路：向量、中文 bigram 关键词、知识图谱 |
| 怎么融合 | RRF，k=60，权重 1.0 / 0.3 / 0.2，再交叉编码器重排 |
| 图谱有用吗 | **没有稳定增益**，实测是负结果，权重从 0.6 降到 0.2 且如实记录 |
| 影像怎么处理 | 不做识别诊断；VLM 客观描述 → 当查询检索文献 → 有证据的辅助解读 |
| 影像相似检索 | 颜色直方图基线，不是医学语义特征 |
| 评测多少题 | 50 题（指南 20 / 综述 20 / 关系型 10），全中文 |
| 三个指标 | R@5 **0.800**、R@10 **0.860**、MRR@10 **0.666**（含重排） |
| 有 GitHub 吗 | 没有，也没公网 Demo，本地一键启动 |
