## 一、推荐用什么打开

### VS Code（推荐主力）

打开 **`rag-project.code-workspace`**（不是直接打开文件夹），这样会得到
四栏工作区：项目根 / 后端 / 前端 / 文档。

```
D:\AI\RAG_project\rag-project.code-workspace
```

**为什么用它**：项目是混合栈，VS Code 对 Python 与 Vue 都够用。
已预置：

| 功能 | 位置 |
|------|------|
| 4 个调试配置 | 按 `F5` 选「启动后端 (FastAPI)」即可带断点启动 |
| 3 个任务 | `Ctrl+Shift+P` → `Tasks: Run Task` |
| 解释器路径 | 已指向 `D:\deep seek test\rag-venv` |
| 排除干扰 | `__pycache__` / `node_modules` / `data` 已隐藏 |

**需要装的扩展**（首次打开时 VS Code 会提示，点安装即可）：

- `ms-python.python` + `ms-python.vscode-pylance` —— Python 跳转与补全

- `ms-python.debugpy` —— 断点调试

**唯一不可替代的场景**：靠"跳转到定义"梳理后端调用链。

→ 选 `D:\deep seek test\rag-venv\Scripts\python.exe`

## 二、按目的选择阅读顺序

### 目的 A：快速理解系统怎么工作（30 分钟）

按数据流读这 5 个文件，就能理解整条链路：

```
1. backend/app/schemas/common.py          数据结构定义（先看 QaRequest/QaResponse）
        ↓
2. backend/app/api/v1/qa.py               接口入口（看请求怎么进来）
        ↓
3. backend/app/services/rag_service.py    ★ 核心：编排整个问答流程
        ↓
4. backend/app/services/hybrid_search.py  ★ 核心：4 路召回 + RRF + 重排
        ↓
5. backend/app/services/citation.py       引用解析与数值核验
```

**`rag_service.py` 的 `answer()` 是全文最重要的一处**，
它把「检索 → 生成 → 引用解析 → 数值核验」串成一条线，读它就懂全局。

### 目的 B：准备答辩提问（重点看这几处）

答辩老师最可能追问的地方，都在这几个文件里，且**注释里已写明设计理由**：

| 可能的提问 | 看哪里 |
|-----------|--------|
| 为什么用 bigram 而不是 pg_trgm？ | `app/core/text_utils.py` 顶部注释（**实测 pg_trgm 忽略非 ASCII**） |
| 为什么关键词检索权重只有 0.3？ | `app/services/hybrid_search.py` 的 `recall_keyword` 文档字符串 |
| 怎么防止大模型编造？ | `app/services/prompts.py` 的 SYSTEM_PROMPT 第 5 条 + `citation.verify_numeric_claims` |
| 提示词能解决幻觉吗？ | `citation.py` 中"数值主张核验"整段注释（**实测提示词无效，22%→26%**） |
| 为什么用本地模型不调 API？ | `app/services/registry.py`（显存分配） |
| 为什么影像解读用云端？ | `app/services/vision_client.py` 顶部（**低频 vs 高频的资源取舍**） |
| RRF 有什么缺陷？ | `app/services/fusion.py` + README 4f.3 发现 3 |
| 知识图谱为什么有效？ | `app/services/graph_search.py` 顶部设计说明 |

### 目的 C：写论文的技术章节

| 论文小节 | 对应代码 |
|---------|---------|
| 知识库构建 | `app/etl/` 全部（pubmed_client / chunker / ingest / classifier） |
| 多路召回与融合 | `app/services/hybrid_search.py` + `fusion.py` + `repositories/search_repo.py` |
| 答案生成与引用溯源 | `app/services/rag_service.py` + `prompts.py` + `citation.py` |
| 知识图谱 | `app/services/extraction.py`（本体定义）+ `graph_client.py` + `graph_search.py` |
| 影像辅助解读 | `app/services/vision_client.py` + `image_analysis.py`（**三段式链路**） |
| 多轮对话 | `app/services/conversation.py`（**查询改写**） |
| 评测与实验 | `app/eval/` 全部 + `scripts/make_paper_materials.py` |

**强烈建议**：写论文时直接引用代码里的**中文注释**。
这些注释记录了"为什么这样设计"以及实测数据，
比事后回忆准确得多。例如 `config.py` 里就写了 max_tokens 的实测依据：

```
=512  时 100% 返回空答案
=1024 时 4 次中出现 1 次空答案
=4096 时 复杂医学问题仍偶发耗尽（推理内容可达 14000 字符）
```

## 五、两个阅读提示

**1. 中文注释是这个项目的知识库**

代码里有大量「为什么这样做」的说明，包括失败的尝试与实测数字。
这些是论文写作和答辩的素材来源。**不要只读代码逻辑，注释更重要。**

**2. 注意区分「能跑」与「已验证」**

认证与角色权限、典型病例管理、影像相似检索等模块已接入前后端；
README 顶部的阶段表和本说明书记录了当前实现范围。阅读时仍应区分
「接口可用」与「已用真实业务数据验证」，尤其是病例库目前没有病例记录。
