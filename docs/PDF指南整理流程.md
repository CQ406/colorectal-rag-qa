# PDF 指南整理流程

把下载的 PDF 指南整理成知识库可导入的 Markdown。本文件记录流程、
踩过的坑，以及复现命令。

---

## 一、为什么不能直接导入 PDF

`manual` 命令只接受 Markdown。PDF 需要先抽取正文，而中文期刊 PDF 的抽取
有若干固有问题（下表为实测遇到的全部问题）：

| 问题 | 现象 | 处理 |
|------|------|------|
| 每页重复页眉 | 「中华胃肠外科杂志2019年3月第22卷第3期...」混入正文 | 按「同一行在多页重复」自动识别删除 |
| 上标引用标记 | `［1⁃3］` `［28］` 夹在文字中 | 正则删除（保留正文数字） |
| **固定宽度换行** | 一句话被切成 2~3 行 | 行尾无终止标点则与下一行合并 |
| **标题与正文粘连** | `## 四、...分级处理原则外科医生应该...` | 在标题性结尾词后切开 |
| **编号小节丢标题** | `### 1. 性别：...` 后面粘上 `（专家赞成率）2.美国麻醉师协会...` | 按 `N.` 编号断行，提升为 `###` |
| 段落过长 | 单段 2000+ 字，检索时稀释相关性 | 按句末标点切到 400~700 字 |
| 表格乱文 | 「表1」内容与正文流混排 | **不自动还原**，插入提示由人工补录 |
| 页脚水印 | `·指南与共识·`、`扫码阅读电子版`、页码 | 正则删除 |
| **UTF-8 BOM** | 首行 `# 标题` 变成 `\ufeff# 标题`，**整篇被静默跳过** | 用 `utf-8-sig` 读取 |

### 表格为什么不自动还原

PDF 表格在文本流中没有行列结构，自动还原极易造成**数值错位** ——
在医学文本里，把「A 组 5%」和「B 组 8%」弄反的后果比缺失更严重。
因此一律插入提示，由人工按原文补录。

## 二、完整流程

### 步骤 1：抽取草稿

```powershell
cd D:\AI\RAG_project\backend
$env:PYTHONPATH = "D:\AI\RAG_project\backend"
$py = "D:\deep seek test\rag-venv\Scripts\python.exe"

# 单篇
& $py scripts\extract_guideline_pdf.py "D:\AI\毕设\PDF\某指南.pdf" `
     "D:\AI\RAG_project\data\manual_draft\某指南.草稿.md"

# 批量（生成全部草稿并评级）
& $py scripts\batch_extract_pdfs.py
```

批量脚本会输出评级表：

    好  —— 汉字占比 ≥60%、无异常巨行、章节数 ≥3，可直接整理
    可  —— 汉字占比 ≥40%，需少量清理
    差  —— 合并失控（最长行上万字符），需按版面块重写提取器或人工整理

### 步骤 2：清理结构

```powershell
& $py scripts\clean_draft.py <草稿.md> <清理后.md>
```

处理内容：修断裂标题、拆超长段落、剔除表格乱文与页脚残留。

### 步骤 3：人工核对与修正

**这一步不可省略。** 自动处理只能解决结构问题，以下需人工判断：

- **数值核对**：每处剂量、阈值、百分比都要对照原文
- **表格补录**：脚本会在表格位置插入提示，需按原文补
- **标题层级**：个别小节可能仍带编号前缀，不影响检索但可美化
- **丢失内容**：核对保留率（脚本会打印），若低于 85% 需检查

### 步骤 4：写入 `data/manual/`

文件名**不带下划线前缀**（下划线开头会被当作参考资料跳过）。

元数据格式：

```markdown
# 指南标题

**作者**：编写组
**期刊**：期刊名
**年份**：2019
**证据等级**：guideline
**分期**：postop

## 一级章节

正文……

## 另一章节

正文……
```

### 步骤 5：导入并验证

```powershell
& $py -m app.etl.cli manual --dry-run    # 预览：确认章节数与字数
& $py -m app.etl.cli manual              # 导入
```

验证检索（用中文提问，看第 1 名是否命中新导入的章节）：

```powershell
& $py -c "..."    # 见 data/manual/README.md 的验证脚本
```

## 四、41 份 PDF 的抽取质量

| 评级 | 数量 | 说明 |
|------|------|------|
| 好 | 3 | 可直接整理 |
| 可 | 9 | 需少量清理 |
| 差 | 29 | 合并失控，最长行达 76981 字符 |

**「差」的根因**：这些 PDF 用双栏排版且行内空格不足，按标点判断行结束的
启发式失效 —— 左栏末尾与右栏开头被连成一句，几十行并成巨行。

**改善途径**（按成本从低到高）：

1. 提供 **Word 版或网页版**原文（抽取质量远好于 PDF）
2. 用 `page.get_text("blocks")` + 栏检测重写提取器
3. 人工整理（慢但可靠）

## 五、踩过的坑（供后续参考）

### 坑 1：CJK 正则误用 raw string

```python
# 错误：\u4e00 不会被解析为转义序列，正则变成匹配字面串 "u4e00"
_CJK_RE = re.compile(r"[\u4e00-\u9fff]")
# 正确
_CJK_RE = re.compile("[\u4e00-\u9fff]")
```

**为什么难发现**：`_has_cjk("吻合口漏")` 恰好返回 `True` ——
5 个汉字的码点落在那段字面区间内。症状是「原始 XML 有 14 篇中文，
解析器取到 0 篇」，靠对照才逼出来。

### 坑 2：UTF-8 BOM 导致整篇静默跳过

文件首行 `# 标题` 带 BOM 后变成 `\ufeff# 标题`，正则匹配失败，
报「缺少一级标题」并跳过整篇。**而导入日志显示「更新 1 篇」（那是另一篇的统计）**，
极具误导性。

已在 `manual_import.load_directory` 改用 `utf-8-sig` 读取，并在解析层加兜底剥离。

### 坑 3：按主题分桶会丢弃内容

初版整理脚本按主题关键词把段落分桶，结果 69 段中 35 段因不含主题词被丢弃
（占一半），包括「肿瘤直径≥5 cm，吻合口漏的发生率增加 4 倍」这类关键证据句。

**教训**：整理的作用是改善可读性，**不是做内容筛选**。
现改为保留原文顺序与结构，只修碎片。
