## 一、填写人与署名规则（先读）

1. **本表必须由具备资质的临床人员填写**：结直肠外科执业医师，或经科室授权、具备相应临床资质的复核人（如高年资主治及以上）。开发者、数据工程师、学生不得代填，也不得「帮忙补全」。
2. 复核人须逐条对照原文 XML 核对来源、诊断、术式、许可与脱敏情况，不能只依据本表或中文标题判断。
3. **为什么不能由开发者代填复核意见**：这些病例一旦 `is_public` 置为 true，就会出现在系统演示、中期答辩材料和检索结果中，等同于对外发布；`review_note` / `reviewed_by` / `reviewed_at` 会被写入数据库并进入审计日志，成为「已由临床复核」的证据。开发者代填等于伪造医疗审核记录，既误导答辩专家与后续使用者，也可能让未经核实的病例被当作教学材料传播。
4. 复核人填完后，由本人（或经其确认的经办人）把结论誊入 `data/cases/case_review.csv`，再运行发布脚本。**脚本只搬运复核结论，不产生结论**。

## 四、使用说明（填表 → 跑脚本 → 验证）

1. **填表**：复制模板并交给复核人填写（不要直接改模板）：

   ```powershell
   copy data\cases\case_review_template.csv data\cases\case_review.csv
   ```

   CSV 列：`case_code,approved,deidentified,review_note,reviewed_by,reviewed_at`。
   `approved` 与 `deidentified` 填 `yes`；`review_note` ≥ 10 字；`reviewed_by` 为复核人姓名；`reviewed_at` 为复核人实际复核日期（`YYYY-MM-DD`）。
   不同意发布、未脱敏或尚未复核的条目**留空即可**，脚本会逐条拒绝并打印原因。

2. **预演（不写库）**：

   ```powershell
   cd D:\AI\RAG_project\backend
   python -m scripts.publish_reviewed_cases --dry-run
   ```

   逐条核对「通过 / 拒绝」是否符合预期。`--dry-run` 只打印将要执行的动作，不修改数据库。

3. **发布**（确认预演结果后）：

   ```powershell
   python -m scripts.publish_reviewed_cases
   ```

   脚本只更新 CSV 中通过校验的条目：写入 `review_note` / `reviewed_by` / `reviewed_at`，并把 `is_public` 置为 true；不修改任何临床字段，也不调用模型。

4. **验证**（只读）：

   ```sql
   SELECT count(*) FROM kb_case WHERE is_public;                -- 期望等于通过条数
   SELECT case_code, reviewed_by, reviewed_at, left(review_note, 40)
   FROM kb_case WHERE is_public ORDER BY case_code;
   ```

   或访问 `GET http://127.0.0.1:8000/api/v1/cases`（只返回公开病例），确认列表条数与内容。

5. **撤回**：脚本不提供撤回。已发布条目需管理员通过 `PATCH /api/v1/cases/{id}` 将 `is_public` 置为 false，并保留审计记录。
