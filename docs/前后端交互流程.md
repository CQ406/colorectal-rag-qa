# 前后端交互流程

> 依据当前代码（2026-11-16）。前端 `frontend/src`，后端 `backend/app`。

---

## 一、总览：两种传输通道

| 通道 | 用于 | 实现 |
|---|---|---|
| **普通 HTTP（JSON）** | 登录、列表、详情、维护操作、影像上传 | axios 实例 `http`，拦截器统一注入令牌与处理错误 |
| **SSE（Server-Sent Events）** | 问答正文逐字输出（`/qa/stream`、`/chat/stream`） | 原生 `fetch` + `ReadableStream`，因为 axios 浏览器端拿不到流 |

**为什么流式不走 axios**：axios 的浏览器适配层会把响应体整体读完后才回调，拿不到增量。

**地址解析**：

```
前端 BASE = '/api'                        （相对路径）
        ↓ 开发环境经 Vite 代理
vite.config.ts: proxy '/api' → http://127.0.0.1:8000
        ↓
后端路由前缀 /api（app/core/config.py: api_prefix）
```

代理里对流式响应专门关掉了缓冲（`X-Accel-Buffering: no`、`Cache-Control: no-cache`），否则 Vite 的 http-proxy 会把整段答案攒到最后一次性吐出，看起来"没有流式效果"。

## 二、认证：令牌放在哪、怎么带

```
POST /api/auth/login  {username, password}
   ↓ 后端校验 bcrypt、记失败次数、超限锁定
   ↓ 返回 {access_token, user}
前端 localStorage：
   cr_access_token   （JWT）
   cr_user           （用户信息 + 角色 + 权限）
```

| 场景 | 令牌怎么带 |
|---|---|
| axios 请求 | 请求拦截器读 `localStorage` 注入 `Authorization: Bearer …` |
| SSE 请求 | `ssePost` 里手动读同一次 `localStorage` 注入（曾经漏了，导致多轮会话归属错乱、历史 404） |
| `<img>` 原图 | 无法带头，因此影像原图/列表在公开白名单内 |

**401 的两种含义必须区分**（已修）：

```
请求 URL 含 /auth/login  → 账号或口令错误（保留后端原文案，含"锁定"提示）
其它 401                → 会话过期：清 localStorage → 广播 cr:unauthorized
                          → main.ts 监听：清 Pinia 状态 → 跳转 /admin 登录页
```

## 三、普通请求的完整链路

以「文献列表」为例：

```
Views/KnowledgeView.vue
   ↓ 调用
api/client.ts  api.kbDocuments({page, size})
   ↓ http.get('/admin/kb/documents', {params})
请求拦截器：注入 Authorization
   ↓
Vite 代理 → 后端
   ↓
api/v1/knowledge.py  list_documents()  ← 权限依赖 require_permission
   ↓
repositories/kb_repo.py  list_documents()  ← 分页 + 排序 SQL
   ↓ JSON（UTF8JSONResponse 显式 charset）
响应拦截器：
   成功 → 返回 data
   失败 → 提取后端 detail，转成可读 Error 抛给调用方
   ↓
View 里 catch 后展示提示（空表 vs 加载失败要能区分）
```

**统一的错误出口**：后端所有异常都转成 `{detail: "..."}`；前端拦截器把它包成 `Error(detail)`，页面只负责显示，不再各自解析状态码。

## 四、单轮问答：SSE 事件流

```
QaView.vue  send()
   ↓
stores/chat.ts  ask(text)
   ↓ 先插入用户消息 + 助手占位（界面立刻有反馈）
api/client.ts  streamQa(params, handlers)
   ↓ ssePost('/qa/stream', body, handlers)
POST /api/qa/stream
   ↓
api/v1/qa.py  qa_stream()
   ↓
services/rag_service.py  answer_stream()  ← 检索 → 门槛 → 生成 → 校验
   ↓ 逐事件写成 SSE
```

**线上格式**（每帧以空行结束）：

```
data: {"type":"retrieval","data":{"count":5,"top_score":0.98,"evidences":[...]}}

data: {"type":"delta","data":{"text":"## 一、术前环节"}}

data: {"type":"delta","data":{"text":"…"}}

data: {"type":"done","data":{"answer":"…","citations":[...],"invalid_citations":[],"timings":{...}}}

```

**五种事件**

| type | 何时 | 前端动作 |
|---|---|---|
| `retrieval` | 检索完成 | 立即渲染右侧引用面板（不必等答案） |
| `delta` | 每个文本增量 | 追加到正文，滚动到底 |
| `done` | 生成完成 | 用完整答案覆盖（防增量丢失）、渲染校验结果、复位状态 |
| `error` | 出错或拒答 | 显示错误；`reason=no_evidence` 时按提示而非故障处理 |
| `meta` | 仅多轮会用 | 显示改写后的查询、分期、意图 |

**前端解析要点**（`ssePost`）：

```
TCP 分片 → 缓冲区累积文本 → 按 "\n\n" 切出完整事件
        → 取所有以 data: 开头的行拼接 → JSON.parse
```

直接对每个 chunk 做 `JSON.parse` 会随机失败（一条事件可能被切成两半）。
解析失败只告警、不中断流；**流结束却没有任何终态事件时**补一次 `onError('回答可能不完整')`，否则界面会永久停在"生成中"。

## 五、多轮会诊：多一个 meta 事件 + 会话恢复

```
POST /api/chat/stream {question, session_id?}
   ↓
api/v1/chat.py
   ├─ conversation_owner()：优先按 Authorization 归属 user:<id>，否则 guest:<cookie>
   ↓
services/conversation.py chat_stream()
   ├─ 查询改写（结合历史解析指代）
   ├─ 意图/分期识别
   ├─ rag_service.answer_stream()  ← 与单轮同一条链路
   └─ done 时：写入会话历史 + sys_qa_log(mode=chat)
   ↓
SSE：meta → retrieval → delta… → done
```

**会话恢复**（刷新/切页后不丢）：

```
前端 sessionStorage: cr.chat.session_id
   ↓ 进入页面 onMounted
GET /api/chat/{session_id}    ← 返回轮次（含引用明细）
   ↓ 重建用户/助手消息、恢复引用面板
404（后端重启/会话过期）→ 清掉本地 id，避免每次进来都失败
```

## 六、影像解读：三段式 + 缓存

```
ImagesView.vue  点「辅助解读」
   ↓ POST /api/images/analyze {image_id, top_k, use_cache}
api/v1/images.py
   ├─ 缓存命中（asset.vlm_analysis 存在）→ 直接跑「检索 + 综合」
   └─ 未命中 → vision_client 调 GLM-4V 生成客观描述 → 缓存 → 检索 → 综合
   ↓ 落库 vlm_interpretation 快照（失败时不落库，避免覆盖旧结果）
   ↓ 写 sys_qa_log(mode=image)
返回 JSON：{description, interpretation, citations, retrieval_query, timings}
```

**上传**走 `multipart/form-data`（`fetch` + `FormData`），其余接口都是 JSON。


## 八、引用面板：详情按需拉取

引用卡片首屏只有片段（后端截断到约 300 字）。点「展开原文」时：

```
GET /api/chunks/{chunk_id}   ← 返回完整正文 + 章节 + 页码 + 是否上架
```

该接口在公开白名单内（与检索一致），未登录也能展开。

## 九、一条时间线：从打开页面到看到答案

```
1. App.vue 挂载 → 读 localStorage 恢复登录态 → auth.refresh() 验证令牌
2. 路由守卫：未登录访问受保护页 → 跳 /admin
3. QaView 挂载 → GET /api/stats、/api/phases 初始化筛选项
4. 用户提问 → 乐观插入用户消息与助手占位
5. POST /api/qa/stream（fetch，带 Bearer）
6. retrieval 事件 → 引用面板立即出现
7. delta 事件 → 正文逐字增长
8. done 事件 → 覆盖完整答案、渲染耗时与校验提示、busy 复位
9. 若中途失败/被中止 → error 或本地 abort → 保留已生成内容并标注
```

## 十一、约定与坑（都踩过）

| 约定 | 原因 |
|---|---|
| 前端统一 `BASE='/api'` | 开发走 Vite 代理，打包后同源部署，无需改代码 |
| 超时 300 秒 | 问答含模型加载与长生成；太短会误判超时 |
| SSE 必须禁缓冲 | 否则代理把整段答案攒到最后一次性返回 |
| SSE 与 axios 都要带令牌 | 只给 axios 加会导致会话归属错乱（历史 404） |
| 流必须有终态兜底 | 无 done/error 时界面会永久"生成中" |
| 401 区分登录接口 | 否则"口令错误"被显示成"登录已过期" |
| 后端显式 `charset=utf-8` | Windows PowerShell 缺 charset 时按 GBK 解码，中文乱码 |
